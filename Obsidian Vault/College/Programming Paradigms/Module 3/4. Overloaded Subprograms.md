## Topic 6: Overloaded Subprograms

**1. The Prerequisite Connection**

- Recall that a **referencing environment** is the collection of all variables and subprograms visible in a specific area of code.
    
- Normally, every subprogram in a single referencing environment must have a totally unique name so the computer doesn't get confused when you call it. Overloading bends this rule.
    

**2. The Definition**

- An overloaded subprogram is a subprogram that has the exact same name as another subprogram within the same referencing environment.
    
- Although it is not strictly necessary, overloaded subprograms usually implement the same logical process, just on different types of data.
    

**3. The "Unique Protocol" Rule (Crucial for the exam)** If two subprograms have the same name, how does the computer know which one you are trying to call?

- Every version of an overloaded subprogram must have a **unique protocol**.
    
- This means it must be completely different from the others in the **number**, the **order**, or the **types** of its parameters.
    
- For functions, it can also differ in its return type.
    
- When the program runs, the meaning of a call to an overloaded subprogram is dynamically determined by looking at the actual parameter list you provided.
    

**4. Real-World Usage & Languages**

- Languages like C++, Java, Ada, and C# natively include predefined overloaded subprograms, and they allow users to write their own.
    
- The most common user-defined overloaded methods in object-oriented languages (like C++, Java, and C#) are **constructors** (e.g., having one constructor that takes no parameters, and another with the same name that takes two integers).
    

**5. A Potential Danger (Good to include for extra marks)**

- You should note that overloaded subprograms that use _default parameters_ can sometimes lead to ambiguous subprogram calls, which will cause compiler errors.
