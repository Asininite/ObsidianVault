## Prerequisite 1: Nested Subprograms

First, we need to understand where a closure even comes from.

- A subprogram is simply a function or a method.
    
- **Nested Subprograms** occur when you define one function directly _inside_ the body of another function.
    
- For example, imagine an "Outer Function" that has its own local variables, and inside it, you write an "Inner Function".
    

## Prerequisite 2: Scope and Lifetime

_(Note: "What is meant by scope and lifetime?" is also a frequent 3-mark KTU question!)_

- **Scope:** This refers to _where_ in the code a variable is visible and can be legally used. In nested subprograms, the inner function can normally "see" and use the local variables of its parent outer function.
    
- **Lifetime:** This refers to _how long_ a variable actually exists in the computer's memory. Normally, when a function finishes executing, all of its local variables are destroyed and wiped from memory to save space.
    

## Prerequisite 3: The Referencing Environment

_(Note: "Explain the term Referencing environment" is another 3-mark PYQ!)_

- A **Referencing Environment** is the complete collection of all the variables that a specific subprogram is allowed to see and use at any given time.
    
- For our "Inner Function", its referencing environment includes its own local variables PLUS the local variables of the "Outer Function" that surrounds it.

**The Problem:**
Imagine you want to use the "Inner Function" somewhere else in your program, long after the "Outer Function" has finished running. According to normal rules, once the "Outer Function" finishes, its local variables die. But the "Inner Function" still needs those variables to work! If it tries to run, it will crash because its referencing environment was destroyed.

## The Solution: Closures

- **Definition:** A closure is a subprogram bundled together with the referencing environment where it was originally defined.
    
- Think of it as a protective bubble. When the inner function is passed around the program, it packs up copies of all the variables it needs from its parent and carries them inside this bubble.
    

**Key Points to Write in Your Exam:**

1. **Definition:** A closure is a subprogram and the referencing environment where it was defined. The referencing environment is needed if the subprogram can be called from any arbitrary place in the program.
    
2. **Unlimited Extent:** For the subprogram to be callable from anywhere, the variables defined in the nesting subprograms cannot just die; they may need lifetimes that last for the entire program. A variable whose lifetime is extended to that of the whole program is said to have an **unlimited extent**.
    
3. **Language Support:** If a static-scoped programming language does not allow nested subprograms, closures are not useful, so such languages do not support them. Closures are heavily supported by functional programming languages, most scripting languages, and C#.
