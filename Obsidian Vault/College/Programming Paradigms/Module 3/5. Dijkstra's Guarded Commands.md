## Topic 5: Dijkstra's Guarded Commands

**1. Introduction (The "Why")** New and quite different forms of selection (if-statements) and loop structures were suggested by Edsger Dijkstra. His goal was to support **nondeterminism** (allowing the program to randomly choose between equally valid paths) and to force programmers to explicitly handle every single possible condition, thereby increasing program reliability.

Each line in these structures consists of a Boolean expression (called a **guard**) and a statement (or statement sequence), which together are called a **guarded command**.

**2. Guarded Selection (The "if" statement)** The selection statement has the following syntax:

Plaintext

```
if <Boolean expression> -> <statement>
[] <Boolean expression> -> <statement>
[] <Boolean expression> -> <statement>
fi
```

- **Syntax details:** The closing reserved word `fi` is simply "if" spelled backward, a concept taken from ALGOL 68. The small blocks `[]` are called **fatbars** and are used to separate the guarded clauses.
    
- **Execution Semantics (How it works):**
    
    1. When the statement is reached, **all** of the Boolean expressions (guards) are evaluated.
        
    2. If exactly one expression is true, its corresponding statement is executed.
        
    3. If **more than one** expression evaluates to true, the system **nondeterministically** (randomly) chooses one of the associated statements to execute. The correctness of the program cannot depend on which one is chosen.
        
    4. If **none** of the Boolean expressions are true, a run-time error occurs, causing program termination. This strict rule forces the programmer to consider and list all possibilities.
        
- **Example (Crucial for the April 2025 question):**
    

Plaintext

```
if i = 0 -> sum := sum + i
[] i > j -> sum := sum + j
[] j > i -> sum := sum + i
fi
```

(If `i = 0` and `j > i` at the same time, the program nondeterministically chooses between the first and third statements. If `i` equals `j` but is not zero, the program crashes with a run-time error because none of the conditions are true.)

**3. Guarded Iteration (The "loop" statement)** The loop structure follows a similar pattern but uses `do` and `od`:

Plaintext

```
do <Boolean expression> -> <statement>
[] <Boolean expression> -> <statement>
od
```

- **Execution Semantics (How it works):**
    
    1. All Boolean expressions are evaluated on each iteration.
        
    2. If more than one is true, one of the associated statements is nondeterministically chosen for execution.
        
    3. After the chosen statement executes, the expressions are all evaluated again.
        
    4. The loop only **terminates** when all Boolean expressions evaluate to false simultaneously.

## How to write it in the exam:

If they ask for 6 marks, provide:

1. The brief definition of what a guard and a guarded command are.
    
2. The syntax and semantics of the **Selection (`if-fi`)** structure (emphasize the run-time error if all are false).
    
3. The simple example block for the selection structure.
    
4. The syntax and semantics of the **Iteration (`do-od`)** structure (emphasize that it loops until everything is false).
