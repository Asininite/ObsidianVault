### **Topic 1: Smart Contracts, Templates, and Oracles**

**1. Smart Contracts & Properties** A smart contract is a secure and unstoppable computer program representing an agreement that is automatically executable and enforceable. They are self-enforcing rather than legally enforceable; they simply do exactly what they are programmed to do.

Every smart contract must have these **four exact properties**:

1. **Automatically executable:** Runs on a blockchain without any human intervention.
    
2. **Enforceable:** All contract conditions are enforced automatically.
    
3. **Semantically sound:** Tamper-proof and runs with absolute security guarantees.
    
4. **Secure and unstoppable:** Ensures that the contract always produces the exact same output for a specific input, regardless of external factors.
    

**2. Smart Contract Templates & DSLs** Instead of building complex contracts from scratch using General Purpose Languages (GPLs), developers use templates. These are written using **Domain-Specific Languages (DSLs)**, which have a small set of features optimized for a specific domain (like insurance or energy derivatives). There are even Graphical DSLs that allow domain experts (like lawyers) to design contracts using a user interface without writing code.

**3. Oracles & The Generic Data Flow** The biggest limitation of a smart contract is that it cannot access external, real-world data (like stock prices or weather).

- **Definition:** An Oracle is a trusted interface that delivers data from an external source to smart contracts securely.
    
- **The Data Flow:** The smart contract sends a request to the Oracle. The Oracle fetches data from external _Data Sources_ and sends it to an _Attestation Service_. Finally, the data is sent back to the Oracle with authenticity proof, which then securely feeds it into the smart contract.
    

**4. Types of Oracles (Crucial for Exams)**

- **Software Oracles:** Handle data available over the internet, like e-commerce or flight data.
    
- **Hardware Oracles:** Fetch real-world data from physical IoT devices and sensors.
    
- **Decentralized Oracles:** Source data using distributed consensus mechanisms to ensure authenticity without relying on one single entity.
    
- **Computation Oracles:** Allow computing-intensive calculations to be performed off-chain, returning the verified results to the blockchain.
    
- **Aggregation-based Oracles:** Source a single value (like a stock price) from many different feeds to prevent reliance on a single risky feed.
    
- **Crowd-wisdom Driven Oracles:** Aggregate information from multiple public sources (like election results) when a single source isn't trusted.
    
- **Smart Oracles:** Oracles with the added capability of executing contract code.
