### **Topic 5: Transactions (UTXO) and The Mining Process**

**The Concept (How to understand it):**

Bitcoin does not use traditional bank accounts. In a bank, you have a single "balance" that goes up or down. In Bitcoin, your balance is simply the sum of individual chunks of digital cash you own, called **UTXOs (Unspent Transaction Outputs)**.

Think of UTXOs exactly like physical cash. If you have a ₹500 note and you want to buy a ₹100 coffee, you don't "subtract 100" from the note. You hand over the entire ₹500 note (the Input), the cashier keeps ₹100 (Output 1), and hands you back a new ₹400 note as change (Output 2). Your original ₹500 note is now "spent" and destroyed. Bitcoin works exactly this way.

**The Miners:**

Miners are the network's auditors. Their job is to take pending transactions, verify that the inputs are valid (preventing double-spending), bundle them into a block, and solve the Proof of Work (PoW) puzzle to lock them onto the blockchain forever.

### **PYQs on Topic 5**

**PYQ 1: Describe the various fields that make up a transaction in Bitcoin. (April 2025 - 7 Marks)**

- **Answer:** A standard Bitcoin transaction contains the following structural fields:
    
    1. **Version Number:** Indicates which set of rules this transaction follows.
        
    2. **Input Counter:** The number of inputs included in the transaction.
        
    3. **List of Inputs:** Points to the previous UTXOs being spent. It includes:
        
        - The previous transaction ID (Hash).
            
        - The specific Output Index of that transaction.
            
        - An unlocking script (the digital signature proving ownership).
            
    4. **Output Counter:** The number of outputs being created.
        
    5. **List of Outputs:** The new UTXOs being created. It includes:
        
        - The Value (the amount of Bitcoin).
            
        - A locking script (the cryptographic puzzle locking the funds to the receiver's address).
            
    6. **Locktime:** Specifies the earliest time or block height the transaction can be added to the blockchain.
        

**PYQ 2: Explain Unspent Transaction Output (UTXO) and its use in transaction verification. (Oct 2023 - 7 Marks)**

- **Answer:**
    
    - **Definition (3 Marks):** UTXO stands for Unspent Transaction Output. It represents a discrete chunk of cryptocurrency tied to a specific owner's address. To send Bitcoin, a user must gather existing UTXOs they own to use as "Inputs," completely consume them, and create new UTXOs as "Outputs" for the receiver (and any "change" back to themselves).
        
    - **Use in Verification (4 Marks):** When a transaction is broadcast, mining nodes verify it by checking the global UTXO set.
        
        - They verify that the referenced UTXO actually exists in the database.
            
        - They ensure the UTXO has not already been spent in another transaction (preventing double-spending).
            
        - They verify that the digital signature provided in the input mathematically matches the public key that the original UTXO was locked to.
            

**PYQ 3: What is the role of a Bitcoin miner? Explain the mining process used in Bitcoin with the help of a diagram. (April 2025 / June 2023 - 7 Marks)**

- **Answer:**
    
    - **Role (2 Marks):** Miners listen for transactions, validate them against network rules, group them into blocks, solve the computationally difficult Proof of Work (PoW) puzzle, and secure the network. They introduce new Bitcoin into circulation via block rewards.
        
    - **Mining Process (3 Marks):**
        
        1. **Candidate Block:** A miner creates a temporary "candidate block".
            
        2. **Coinbase Transaction:** The miner adds a special first transaction called the Coinbase transaction, which creates new coins and pays the miner their reward.
            
        3. **Adding Transactions:** Validated transactions are pulled from the memory pool and added to the block.
            
        4. **Block Header:** The miner constructs the header, containing the previous block's hash, a Merkle Root of all transactions, a timestamp, the difficulty target, and a random **Nonce**.
            
        5. **Hashing:** The miner repeatedly hashes the header, changing the Nonce each time, until the resulting hash is lower than the network's required target. Once found, the block is broadcasted.
            
    - **Diagram (2 Marks):** _(Draw this block diagram on your paper)_
        
        Plaintext
        
        ```
        [ Block Header ]
        |-- Previous Block Hash
        |-- Merkle Root -----------> [ Merkle Tree of Transactions ]
        |-- Timestamp                   |-- Tx 0 (Coinbase)
        |-- Target Difficulty           |-- Tx 1
        |-- Nonce                       |-- Tx 2
        ```
        

**PYQ 4: What is the significance of the Genesis block in the blockchain? (April 2025 - 3 Marks)**

- **Answer:** * The Genesis block is the very first block ever recorded in a blockchain network (referred to as Block 0).
    
    - It is hardcoded into the client software and serves as the foundational anchor of the entire blockchain.
        
    - Unlike all other blocks, its "Previous Block Hash" field is entirely empty (usually all zeros) because there is no block preceding it to reference.
        

**PYQ 5: What is a Sybil attack, and how does the Bitcoin network prevent it? (Oct 2023 - 3 Marks)**

- **Answer:**
    
    - **Attack:** A Sybil attack occurs when a single malicious entity creates a massive number of fake node identities to gain majority influence and take over a peer-to-peer network.
        
    - **Prevention:** Bitcoin prevents this using the Proof of Work (PoW) mechanism. In PoW, voting power is not based on the number of IP addresses or nodes you own, but on the physical computational power you control. Generating fake identities is cheap, but generating massive computing power is physically constrained and incredibly expensive.
