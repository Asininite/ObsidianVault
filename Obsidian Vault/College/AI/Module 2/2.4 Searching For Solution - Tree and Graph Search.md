### What is a Search Tree?

A **search tree** is an abstract, logical structure built by a search algorithm to explore the paths in a problem's state space. It is _not_ the state space itself, but rather a dynamic representation of the _search process_.

- It starts with the **initial state** as the **root node**.
- The **branches** (or edges) of the tree represent **actions**.
- The **nodes** in the tree represent **states** reached by taking those actions.
- Each node in the tree corresponds to a _specific path_ from the root.
---
### Search Tree vs. State Space Graph

This is the most important distinction to understand.

- **State Space Graph:** This is the _entire_ problem, showing _all possible states_ and the transitions between them. It can have cycles (e.g., A -> B -> A). It's a static, complete representation of the problem.
    
- **Search Tree:** This is a _dynamic_ tree built _on top of_ the state space graph during the search. It shows the specific paths the algorithm has explored. **A tree, by definition, cannot have cycles.**
    

**Key Consequence:** If the state space graph has a cycle (like `A -> B -> C -> A`), the search tree will represent this as an infinitely deep path. A node `A` at depth 0 is _different_ from a node `A` at depth 3.

---

### How is a Search Tree Generated?

A search tree is generated dynamically, node by node, by the search algorithm. This process is called **expanding** nodes.

1. **Start at the Root:** The algorithm begins by creating the **root node**, which contains the **initial state**. This single node is put into the **frontier**.
    
2. **Expand a Node:** The algorithm selects a node from the frontier.
    
3. **Generate Children:** It applies all valid **actions** to the selected node's state.
    
4. **Create Child Nodes:** For each resulting state, it creates a new **child node**. This new node stores:
    
    - The resulting **state**.
        
    - A **parent pointer** back to the node that was just expanded.
        
    - The **action** that was taken.
        
    - The **path cost** (cost from the root to this new child).
        
5. **Update Frontier:** These new child nodes are then added to the frontier, and the parent node is (usually) moved to an "explored set."
    
6. **Repeat:** The algorithm repeats this process, "growing" the tree until a node it selects for expansion contains a **goal state**.
    

The solution path is then found by following the parent pointers from the goal node back up to the root.

---

### Components of a Search Tree Node

A node in a search tree is a data structure that contains more than just the state. It needs the following "infrastructure" to work:

- **`STATE`:** The state in the state space that this node corresponds to (e.g., the 8-puzzle board configuration).
    
- **`PARENT`:** A pointer to the parent node (the node that generated this one). This is essential for reconstructing the path to the goal.
    
- **`ACTION`:** The action that was applied to the parent to create this node (e.g., "Move Blank Left").
    
- **`PATH-COST` (g(n)):** The total cost of the path from the initial state (root) down to this node.
    

---

### "Tree Search" vs. "Graph Search"

This is a final, crucial detail related to search trees. These are two _versions_ of search algorithms.

- **Tree Search:** This version of an algorithm does _not_ keep an "explored set" of nodes it has already visited.
    
    - **Problem:** If the state space has cycles (e.g., `A -> B -> A`), a tree search algorithm (like basic DFS) can get stuck in an **infinite loop**, re-expanding the same states over and over.
        
- **Graph Search:** This version _does_ keep an **explored set (or closed list)**. Before adding a new child node to the frontier, it checks if that node's _state_ has already been explored.
    
    - **Benefit:** This avoids redundant work and prevents infinite loops.
        
    - **Trade-off:** It uses more memory to store the explored set.
        

In practice, for most problems where you can revisit a state, **graph search** is what is actually implemented.
