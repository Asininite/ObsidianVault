Of course. After an agent has **formulated a problem**, the next step is to **Search** for a solution. This is the "thinking" or "reasoning" part of the process. Let's cover this crucial topic in detail.

---

### Search: Finding a Path to the Goal

In AI, **Search** is the process of systematically exploring the **state space** to find a sequence of actions—a **path**—that leads from the **initial state** to a **goal state**.

#### How Search Works: The Frontier

All search algorithms work by building a **search tree**. The root of the tree is the initial state. As the algorithm explores, it **expands** a node by applying the successor function to generate its children (the states reachable from that node).

The core of every search algorithm is a data structure called the **frontier** (also known as the **open list**).

- **Frontier:** A list of nodes that have been generated but not yet expanded.
- The search process is simple:
    1. Start with the initial state in the frontier.
    2. Loop:
        a. If the frontier is empty, then fail (no solution found).
        b. Choose a node from the frontier to expand.
        c. If the chosen node is a goal state, return the solution (the path to that node).
        d. Otherwise, expand the node, add its children to the frontier, and repeat.

The _only_ difference between the various search algorithms is the **strategy they use to choose the next node from the frontier**.

#### Measuring Search Performance

We evaluate and compare search algorithms using four key criteria:

1. **Completeness:** Is the algorithm guaranteed to find a solution if one exists?
    
2. **Optimality:** Does it find the solution with the lowest path cost?
    
3. **Time Complexity:** How many nodes does it generate/expand? This is often expressed using:
    
    - **b:** branching factor (the maximum number of successors of any node).
        
    - **d:** depth of the shallowest goal node.
        
    - **m:** maximum depth of the state space.
        
4. **Space Complexity:** How much memory does it need to store the frontier?
    

---

### Uninformed (Blind) Search Strategies

These strategies have no additional information about the state space beyond the problem definition. They don't know if one state is "better" or "closer" to the goal than another.

#### 1. Breadth-First Search (BFS)

- **Strategy:** Expands the shallowest unexpanded node first. It explores the search tree level by level.
    
- **Data Structure:** Uses a **FIFO (First-In, First-Out) Queue** for the frontier.
    
- **Performance:**
    
    - **Completeness:** **Yes**. It will eventually find the solution.
        
    - **Optimality:** **Yes**, but only if all step costs are the same (e.g., each move costs 1).
        
    - **Time Complexity:** $O(b^d)$.
        
    - **Space Complexity:** $O(b^d)$. This is its biggest weakness, as it must store the entire frontier in memory, which grows exponentially.
        

#### 2. Uniform-Cost Search (UCS)

- **Strategy:** A variation of BFS. Instead of expanding the _shallowest_ node, it expands the node with the **lowest path cost (g(n))** from the start.
    
- **Data Structure:** Uses a **Priority Queue** for the frontier.
    
- **Performance:**
    
    - **Completeness:** **Yes**.
        
    - **Optimality:** **Yes**, always. This is its main advantage over BFS, as it handles varying step costs correctly.
        
    - **Time & Space Complexity:** Roughly $O(b^d)$, but can be much worse if step costs vary widely.
        

#### 3. Depth-First Search (DFS)

- **Strategy:** Expands the _deepest_ unexpanded node first. It goes down one path as far as possible before backtracking.
    
- **Data Structure:** Uses a **LIFO (Last-In, First-Out) Stack** for the frontier.
    
- **Performance:**
    
    - **Completeness:** **No**. It can get stuck in infinite loops in graphs with cycles.
        
    - **Optimality:** **No**. It returns the first solution it finds, which may not be the shallowest or cheapest one.
        
    - **Time Complexity:** $O(b^m)$, where _m_ is the maximum depth. This can be much larger than _d_.
        
    - **Space Complexity:** $O(bm)$. This is its **single biggest advantage**. Its memory requirement is linear, not exponential, making it suitable for very large state spaces.

### Informed (Heuristic) Search Strategies

These strategies use problem-specific knowledge to guide the search, making them much more efficient than blind search.

#### The Heuristic Function: $h(n)$

An informed search algorithm uses a **heuristic function**, denoted as **$h(n)$**.

- **Definition:** $h(n)$ is an **estimated cost** of the cheapest path from the state at node `n` to a goal state.
    
- **Example (8-Puzzle):**
    
    - $h_1(n)$ = Number of misplaced tiles.
        
    - $h_2(n)$ = Sum of the Manhattan distances of the tiles from their goal positions. (Manhattan distance is the number of horizontal and vertical steps needed to move a tile to its correct spot).
        

The heuristic gives the search algorithm a "sense of direction."

#### 1. Greedy Best-First Search

- **Strategy:** Expands the node that _appears_ to be closest to the goal, according to the heuristic. It's "greedy" because it follows the path that looks best at the moment, without considering the cost so far.
    
- **Evaluation Function:** **$f(n) = h(n)$**.
    
- **Performance:**
    
    - **Completeness:** No. It can be misled by a bad heuristic and get stuck in loops.
        
    - **Optimality:** No.
        

#### 2. A* Search (A-star Search)

A* is the most widely known and effective informed search algorithm. It combines the strengths of Uniform-Cost Search and Greedy Best-First Search.

- **Strategy:** It expands the node that has the lowest value of its evaluation function, **$f(n)$**.
    
- **Evaluation Function:** **$f(n) = g(n) + h(n)$**
    
    - **$g(n)$:** The actual cost of the path from the start node to node `n` (the UCS part).
        
    - **$h(n)$:** The estimated cost from node `n` to the goal (the Greedy part).
        
- A* balances the cost of the path so far with an estimate of the cost remaining, trying to find the overall cheapest solution.
    

##### Optimality of A*: Admissibility and Consistency

> **⭐ Exam Focus:** This is a guaranteed high-mark question.

- A* is **optimal** (guaranteed to find the lowest-cost solution) if its heuristic, $h(n)$, is **admissible**.
    
- **Admissible Heuristic:** A heuristic is admissible if it **never overestimates** the true cost to reach the goal. It is always optimistic or perfectly accurate.
    
    - Formally: For every node `n`, $h(n) \leq h^*(n)$, where $h^*(n)$ is the true cost from `n` to the goal.
        
    - **Example:** The "number of misplaced tiles" heuristic is admissible because every misplaced tile must be moved _at least once_. The true cost will be at least that much. Manhattan distance is also admissible.
        
- **Consistent Heuristic (Monotonicity):** A stronger condition. A heuristic is consistent if, for every node `n` and every successor `n'` of `n` generated by any action `a`, the estimated cost of reaching the goal from `n` is no greater than the step cost of getting to `n'` plus the estimated cost of reaching the goal from `n'`.
    
    - Formally: $h(n) \leq c(n, a, n') + h(n')$.
        
    - **If a heuristic is consistent, it is also admissible.** The advantage of consistency is that it guarantees that when A* selects a node for expansion, it has already found the optimal path to that node.1
