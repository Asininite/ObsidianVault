> **Greedy Best-First Search** and **A* Search** are the most famous examples of **Informed Search** strategies.

The _only_ difference between an uninformed search and an informed search is the use of a heuristic.

- **Uninformed (Blind) Search:** (like BFS or DFS) Does **not** use a heuristic. It's "blind" and just systematically explores.
    
- **Informed (Heuristic) Search:** (like Greedy BFS or A*) **Does** use a heuristic function to guide the search, making it "smart".
    
---

### 1. What is a "Heuristic"?

In general, a **heuristic** is a mental shortcut, a "rule of thumb," or an "educated guess" used for problem-solving.

- It's a practical, fast, and efficient strategy that is **not guaranteed to be perfect** or optimal, but is good enough for the purpose of solving a problem.
    
- For example, when you're trying to drive to a destination, a common heuristic is "drive in the general direction of the destination." This is usually a good idea, but not always optimal (it doesn't account for one-way streets or highway access).
    

---

### 2. What is a "Heuristic Function"?

In Artificial Intelligence, a **heuristic function** is the _implementation_ of that "rule of thumb."

It is a function, commonly written as **$h(n)$**, that takes a state `n` (a node in the search tree) as input and returns a number. This number is an **estimate** of the cost of the cheapest path from that state `n` to the goal state.

- $h(n) = \text{Estimated cost from } n \text{ to Goal}$
    

The algorithm uses this function to decide which node in the frontier (its "to-do" list) to explore next, prioritizing the one that _appears_ to be closest to the solution.

---

### 3. How Heuristics Are Used in Greedy BFS and A*

This is how these two **informed** algorithms use the heuristic function. They are both types of "Best-First Search," meaning they expand the node that looks "best" according to some evaluation function, **$f(n)$**.

#### Greedy Best-First Search

Greedy BFS is "greedy" because it _only_ cares about the heuristic. It always expands the node that _looks_ closest to the goal, ignoring the cost it took to get there.

- **Evaluation Function:** **$f(n) = h(n)$**
    
- **How it works:** It always chooses the node with the lowest $h(n)$ value.
    
- **Why it's flawed:** It can be easily fooled. A path might look close to the goal (low $h(n)$) but be at the end of a very long and expensive path (high $g(n)$). It's fast but **not optimal**.
    

#### A* Search

A* is the "smarter" algorithm. It balances _both_ the cost to get to a node and the estimated cost from that node to the goal.

- **Evaluation Function:** **$f(n) = g(n) + h(n)$**
    
- **How it works:**
    
    - **$g(n)$** = The _actual_ cost of the path from the start node to node `n`.
        
    - **$h(n)$** = The _estimated_ cost from node `n` to the goal (the heuristic).
        
- It chooses the node with the lowest $f(n)$ value. By combining $g(n)$ and $h(n)$, it finds a path that is both low-cost _and_ heading in the right direction.
    
- **Why it's powerful:** A* is **optimal** (it's guaranteed to find the cheapest path) as long as its heuristic function $h(n)$ is **admissible** (meaning it _never overestimates_ the true cost).

Here's a detailed lesson on Best-First Search and Greedy Best-First Search, two important topics in informed search.

---

### 1. What is "Best-First Search"?

First, it's important to understand that **"Best-First Search"** is a _family_ of search algorithms, not just one specific method.

- A Best-First Search algorithm is any search that uses an **evaluation function, $f(n)$**, to decide which node in the **frontier** to expand next.
    
- It works by expanding the node that has the "best" (usually the lowest) $f(n)$ value.
    
- It uses a **priority queue** to store the frontier, with the nodes sorted by their $f(n)$ value.
    

Both **Greedy Best-First Search** and **A*** are the two most famous types of Best-First Search.

---

### 2. Greedy Best-First Search (Greedy BFS)

This is the simpler of the two. The name "greedy" tells you everything: it _greedily_ chooses the node that _looks_ closest to the goal _right now_, without considering the cost it took to get there.

#### How It Works

Greedy BFS uses an evaluation function **$f(n) = h(n)$**.

- **$h(n)$** is the **heuristic function**, which _estimates_ the cost from node `n` to the goal.
    
- The algorithm expands the node with the lowest $h(n)$ value, believing it's the closest to the goal.
    

#### Performance (Evaluation)

- **Completeness: No**. Like DFS, it can be misled by a bad heuristic and follow an infinite path, getting stuck in loops.
    
- **Optimality: No**. Because it's "greedy," it can be easily fooled. It will follow a path that _looks_ short (low $h(n)$) even if it's a trap, ignoring a slightly "uglier" path that is actually the optimal one.
    
- **Time Complexity:** $O(b^m)$ in the worst case (where $m$ is the maximum depth).
    
- **Space Complexity:** $O(bm)$ in the worst case, as it stores nodes in the frontier.
    

---

### 3. Example: Why Greedy BFS Fails (vs. A*)

This example clearly shows the flaw of Greedy BFS.

**Problem:** Find the cheapest path from **Start (S)** to **Goal (G)**.

**Nodes and Costs:**

- Path S $\rightarrow$ A: cost = 1
    
- Path S $\rightarrow$ B: cost = 5
    
- Path A $\rightarrow$ G: cost = 20
    
- Path B $\rightarrow$ G: cost = 5
    

**Heuristic Values ($h(n)$):**

- $h(S) = 10$
    
- $h(A) = 4$
    
- $h(B) = 6$
    
- $h(G) = 0$
    

#### Trace 1: Greedy Best-First Search ($f(n) = h(n)$)

1. **Initialize Frontier:** `{S(h=10)}`
    
2. **Expand S**. Add its children (A, B) to the frontier.
    
3. **Frontier is now:** `{A(h=4), B(h=6)}`
    
4. **Choose:** The algorithm _greedily_ chooses **A** because its heuristic ($h=4$) is lower than B's ($h=6$).
    
5. **Expand A**. Add its child (G) to the frontier.
    
6. **Frontier is now:** `{G(h=0), B(h=6)}`
    
7. **Choose:** The algorithm chooses **G** ($h=0$).
    
8. **Solution Found:** S $\rightarrow$ A $\rightarrow$ G
    
9. **Total Cost:** 1 + 20 = **21**.
    

This is **not** the optimal path. The algorithm was fooled by node A, which _looked_ close to the goal.

#### Trace 2: A* Search ($f(n) = g(n) + h(n)$)

Now, let's see how A* (a _better_ Best-First Search) solves the same problem.

1. **Initialize Frontier:** `{S(f=0+10 = 10)}`
    
2. **Expand S**. Add its children (A, B).
    
    - **A:** $g(A) = 1$ (cost from S). $f(A) = g(A) + h(A) = 1 + 4 = 5$.
        
    - **B:** $g(B) = 5$ (cost from S). $f(B) = g(B) + h(B) = 5 + 6 = 11$.
        
3. **Frontier is now:** `{A(f=5), B(f=11)}`
    
4. **Choose:** The algorithm chooses **A** ($f=5$ is lowest).
    
5. **Expand A**. Add its child (G).
    
    - **G (via A):** $g(G) = 1 + 20 = 21$. $f(G) = g(G) + h(G) = 21 + 0 = 21$.
        
6. **Frontier is now:** `{B(f=11), G(f=21)}`
    
7. **Choose:** The algorithm now chooses **B** (because $f=11$ is lower than $f=21$).
    
8. **Expand B**. Add its child (G).
    
    - **G (via B):** $g(G) = 5 + 5 = 10$. $f(G) = g(G) + h(G) = 10 + 0 = 10$.
        
9. **Frontier is now:** `{G(f=10), G(f=21)}` (It keeps the _better_ path to G).
    
10. **Choose:** The algorithm chooses **G** ($f=10$).
    
11. **Solution Found:** S $\rightarrow$ B $\rightarrow$ G
    
12. **Total Cost:** 5 + 5 = **10**.
    

By balancing _both_ the past cost ($g(n)$) and future estimate ($h(n)$), A* found the true optimal path.

### 4. Previous Year Question (PYQ) Analysis

Let's look at a question from the 2023 exam paper.

> **(2023) Q13:** "Explain Best First Search algorithm. Perform BFS search in the problem given below to reach goal node G from source node S... The heuristic values of A, B, C, D, E, F, G, H, I, S, G are 12, 4, 7, 3, 8, 2, 4, 9, 13, and 0 respectively." 1111

**Important Note:** This question is a classic example of a **typo** on the exam.

- It asks to "Explain Best First Search."
    
- It provides **heuristic values**.
    
- ...But then it asks to "Perform **BFS** search." (Breadth-First Search).
    

**Breadth-First Search (BFS) is an _uninformed_ algorithm and _ignores_ heuristic values.**

Given that heuristic values are provided, the question _almost certainly_ meant to ask you to perform a **Greedy Best-First Search**, which is the simplest _type_ of Best-First Search. Let's solve it that way.

**Problem:** Find the path from S to G using **Greedy Best-First Search ($f(n) = h(n)$)**.

**Heuristic Values:**

- $h(S) = 13$
    
- $h(A) = 12$
    
- $h(B) = 4$
    
- $h(C) = 7$
    
- $h(D) = 3$
    
- $h(E) = 8$
    
- $h(F) = 2$
    
- $h(G) = 0$
    
- $h(H) = 9$
    
- $h(I) = 4$ (Typo in Q paper, $h(G)$ is listed twice, $h(I)$ is 4)
    

#### Trace: Greedy Best-First Search

1. **Initialize Frontier:** `{S(h=13)}`
    
2. **Expand S**. Children are A, B.
    
3. **Frontier:** `{B(h=4), A(h=12)}` (B is chosen, $h=4$ is < 12).
    
4. **Expand B**. Children are E, F.
    
5. **Frontier:** `{F(h=2), E(h=8), A(h=12)}` (F is chosen, $h=2$ is < 8 and 12).
    
6. **Expand F**. Children are I, G.
    
7. **Frontier:** `{G(h=0), I(h=4), E(h=8), A(h=12)}` (G is chosen, $h=0$).
    
8. **Goal Found!**
    

Solution Path: S $\rightarrow$ B $\rightarrow$ F $\rightarrow$ G

Path Cost: 2 + 1 + 3 = 6
