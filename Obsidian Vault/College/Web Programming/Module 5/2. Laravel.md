# **1. BASIC ROUTING IN LARAVEL**

---

Routing in Laravel is the mechanism used to map a URL (like `/home`, `/login`, `/products`) to a piece of code that handles the request.  
In Laravel, routes are defined in the **routes/web.php** file for web pages and **routes/api.php** for API routes.

A route decides **what happens when a user visits a certain URL**.

### **Simple GET Route**

```php
Route::get('/hello', function () {
    return "Hello, Laravel!";
});
```

If the user visits `/hello`, the string “Hello, Laravel!” is returned.

### **Route returning a view**

```php
Route::get('/welcome', function () {
    return view('welcome');
});
```

This loads the Blade template `resources/views/welcome.blade.php`.

### **Route calling a controller method**

```php
Route::get('/users', [UserController::class, 'index']);
```

Here:

- URL: `/users`
    
- Controller: `UserController`
    
- Method: `index()`
    

### **Route parameters**

Parameters allow dynamic values in the URL.

```php
Route::get('/user/{id}', function ($id) {
    return "User ID: " . $id;
});
```

### **Optional route parameter**

```php
Route::get('/user/{name?}', function ($name = "Guest") {
    return $name;
});
```

---

# **KTU-style Short Description of Routing**

“Routing in Laravel defines how URLs are handled by the application. Routes are written in the routes/web.php file and map HTTP requests to closures, views, or controller methods. Laravel supports dynamic parameters, optional parameters, named routes, and routing to controllers, making routing flexible and expressive.”

# **2. CONTROLLERS IN LARAVEL**

---

A **controller** is a PHP class that groups related request-handling logic.  
Instead of writing all code in routes, Laravel encourages keeping logic inside controllers.

Controllers are stored in:

```
app/Http/Controllers/
```

### **Creating a controller**

Use Artisan command:

```
php artisan make:controller UserController
```

This creates:

```php
class UserController extends Controller
{
    public function index() {
        return "User list";
    }
}
```

### **Routing to a controller**

```php
Route::get('/users', [UserController::class, 'index']);
```

### **Controller method with parameter**

```php
public function show($id) {
    return "User ID: " . $id;
}
```

Route:

```php
Route::get('/users/{id}', [UserController::class, 'show']);
```

### **Why controllers are used**

- Keeps routes clean
    
- Groups related logic
    
- Follows MVC pattern
    
- Better maintainability
    

---

# **KTU-style Short Description of Controllers**

“A controller is a class in the app/Http/Controllers directory containing methods that handle incoming HTTP requests. Controllers allow cleaner routing and help implement MVC architecture by separating business logic from routing definitions.”

# **3. ROUTE MODEL BINDING**

---

Route Model Binding allows Laravel to **automatically inject model objects** into your route or controller based on the URL parameter.

Instead of writing:

```php
$user = User::find($id);
```

Laravel fetches the User model automatically.

---

## **Implicit Route Model Binding**

Laravel automatically resolves a model if:

- The route parameter name matches the model variable name
    
- The controller method type-hints the model
    

### **Example**

Route:

```php
Route::get('/user/{user}', [UserController::class, 'show']);
```

Controller:

```php
public function show(User $user) {
    return $user;
}
```

Explanation:

- `{user}` contains the user’s ID
    
- Laravel automatically calls `User::findOrFail()`
    
- Injects the model instance into `$user`
    

If the record is not found → **404 error automatically**.

---

## **Explicit Route Model Binding**

Used when you want to customize how to fetch the model.

In `RouteServiceProvider`:

```php
public function boot()
{
    Route::model('user', User::class);
}
```

OR custom logic using `bind()`:

```php
Route::bind('user', function ($value) {
    return User::where('username', $value)->firstOrFail();
});
```

Useful when the URL contains a **username**, not an ID.

---

# **KTU-Style 8-Mark Answer**

“Route Model Binding in Laravel automatically resolves route parameters into Eloquent model instances. Instead of manually calling Model::find(), Laravel injects the model directly into route or controller methods, reducing boilerplate code. Laravel supports two types of route model binding: implicit and explicit. Implicit binding works when the route parameter name matches the model variable name and the controller method uses type-hinting. Explicit binding allows developers to define custom resolution logic using Route::model() or Route::bind(), which is useful when binding must be done using a non-ID field.”
