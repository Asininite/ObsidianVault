This topic is highly important for 3-, 7-, and 14-mark questions. It is frequently asked in KTU examinations in forms such as “Discuss URI and URL”, “Explain URL structure”, or “Differentiate Internet resources using URI/URL/URN”.

## 1. Introduction to Resource Identification on the Web

The World Wide Web contains billions of documents, media files, and services. For efficient retrieval, every resource must be uniquely and consistently identifiable, regardless of its location or underlying hardware.

To achieve this, the W3C designed a unified addressing model, which consists of:

1. URI (Uniform Resource Identifier)
    
2. URL (Uniform Resource Locator)
    
3. URN (Uniform Resource Name)
    

These three notions collectively define how web resources are located, named, and referenced.

---

## 2. Uniform Resource Identifier (URI)

A Uniform Resource Identifier is a general framework for identifying any resource on the Internet.  
It provides a simple, extensible way to assign identifiers to resources.

A URI may identify a resource by **location**, **name**, or **both**.

General form of a URI:

```
scheme:identifier
```

Examples:

- `http://example.com/books/index.html`
    
- `mailto:someone@example.com`
    
- `urn:isbn:0451450523`
    

A URI is the **superset**, under which URLs and URNs fall.

A URI:

- Must be unique.
    
- Must be persistent over time.
    
- Can be resolved to obtain either the resource or metadata about it.
    

---

## 3. Uniform Resource Locator (URL)

A Uniform Resource Locator is a type of URI that specifies the **location** of a resource on the Internet and the **protocol** used to access it.

A URL answers the question:  
“Where is the resource located, and how can it be retrieved?”

### 3.1 URL Syntax

A standard URL contains the following components:

```
scheme://host:port/path?query#fragment
```

**Scheme:** Defines the protocol  
Examples: `http`, `https`, `ftp`, `mailto`, `file`

**Host:** Domain name or IP address  
Examples: `www.example.com`, `192.168.1.10`

**Port:** Optional; default ports are used if not given  
Examples: HTTP uses 80, HTTPS uses 443

**Path:** Exact location of the resource on the server  
Example: `/courses/module1/index.html`

**Query:** Optional set of parameters, starting with `?`  
Example: `?id=202&sort=asc`

**Fragment:** Section of the document, starting with `#`  
Example: `#introduction`

### 3.2 Examples of URLs

1. `https://www.ktu.edu.in/exam/results.html`
    
    - Scheme: https
        
    - Host: [www.ktu.edu.in](http://www.ktu.edu.in/)
        
    - Path: /exam/results.html
        
2. `http://books.example.com:8080/author/info?id=25`
    
    - Scheme: http
        
    - Host: books.example.com
        
    - Port: 8080
        
    - Path: /author/info
        
    - Query: id=25
        

### 3.3 Importance of URLs

- Enable location of resources across the world
    
- Standardized for compatibility across browsers
    
- Essential for linking in HTML
    
- Used in HTTP requests to identify resources
    

---

## 4. Uniform Resource Name (URN)

A Uniform Resource Name is another subclass of URI, but unlike a URL, it does not give the location of a resource.  
It gives a **persistent, location-independent name**.

A URN answers the question:  
“What is the resource called?”, not “Where is it located?”

Examples:

- `urn:isbn:0-486-27557-4` (book identified by ISBN)
    
- `urn:uuid:6e8bc7e7-dc45-4a65-8473-bd92a3b7182e`
    

URNs are used in systems where the identity of the resource must remain consistent even if it changes location.

---

## 5. Differences Between URI, URL, and URN

|Aspect|URI|URL|URN|
|---|---|---|---|
|Definition|A general identifier for any resource|Identifies resource by location and protocol|Identifies resource by name|
|Scope|Superset|Subset of URI|Subset of URI|
|Location info|May or may not|Always|Never|
|Example|`mailto:abc@gmail.com`|`https://example.com/home`|`urn:isbn:12345`|

Key idea:  
Every URL is a URI, but every URI is not a URL.

## 6. Domain Names

A domain name is a human-readable textual address that maps to an IP address.

Examples:

- google.com
    
- ktu.edu.in
    
- wikipedia.org
    

### Structure of a domain name:

`www.cars.maruthi.org`

- www → host
    
- cars → subdomain
    
- maruthi → second-level domain
    
- org → top-level domain (TLD)
    

TLDs include:

- `.com` (commercial)
    
- `.org` (organizations)
    
- `.edu` (educational)
    
- `.gov` (government)
    
- `.in` (country code)
    

---

## 7. Domain Name System (DNS)

DNS (Domain Name System) is a hierarchical and distributed naming system responsible for translating domain names into IP addresses.

### Functions of DNS:

1. Converts domain names to IP addresses.
    
2. Supports distributed lookup, preventing centralized failure.
    
3. Provides load balancing and caching for faster resolution.
    
4. Enables human-friendly naming rather than numeric addresses.
    

### How DNS works:

1. User enters `www.example.com` into the browser.
    
2. Browser sends query to local DNS resolver.
    
3. Resolver contacts DNS servers (root, TLD, authoritative).
    
4. IP address is returned (e.g., 93.184.216.34).
    
5. Browser uses the IP to contact the destination server.
    

DNS is fundamental to web browsing. Without DNS, URLs would be unusable, and users would need to remember numeric IP addresses.

# EXAM-ORIENTED ANSWERS

## 3-Mark Answer: URI vs URL

A URI (Uniform Resource Identifier) is a general identifier for a resource, whereas a URL (Uniform Resource Locator) is a type of URI that specifies both the location of a resource and the protocol used to access it.  
Example URI: `mailto:someone@gmail.com`  
Example URL: `https://www.example.com/index.html`
