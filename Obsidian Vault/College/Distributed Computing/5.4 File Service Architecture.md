### **Topic: File Service Architecture (Detailed Breakdown)**

**Q: Explain the file service architecture in detail, including the interface operations and access control. [Part B, 14 Marks]**

**Answer:** An architecture that offers a clear separation of the main concerns in providing access to files is structured into three distinct components: a Flat File Service, a Directory Service, and a Client Module.

_(Note: Draw a diagram showing the Client computer containing the "Application Program" and "Client Module", communicating over a network with the Server computer containing the "Directory Service" and "Flat File Service".)_

#### **1. The Flat File Service**

The flat file service is concerned entirely with implementing operations on the actual contents of the files.

- **Unique File Identifiers (UFIDs):** This service does not use text-based filenames. Instead, Unique File Identifiers (UFIDs) are used to refer to files in all requests for flat file service operations. UFIDs are long sequences of bits chosen so that every single file has a completely unique identifier among all the files in the distributed system.
    
- **Interface Operations:** The flat file service provides the following specific Remote Procedure Call (RPC) operations:
    
    - `Read(FileId, i, n) -> Data`: Reads a sequence of up to _n_ items from a file starting at item _i_ and returns it in the Data variable.
        
    - `Write(FileId, i, Data)`: Writes a sequence of Data to a file starting at item _i_, extending the file length if necessary.
        
    - `Create() -> FileId`: Creates a new file of length 0 and delivers a new UFID for it.
        
    - `Delete(FileId)`: Removes the specified file from the file store.
        
    - `GetAttributes(FileId) -> Attr`: Returns the file attributes (metadata) for the file.
        
    - `SetAttributes(FileId, Attr)`: Sets or updates the file attributes.
        

#### **2. The Directory Service**

The directory service provides the mapping between human-readable text names for the files and their corresponding UFIDs.

- **Responsibility:** Clients obtain the UFID of a file by quoting its text name to the directory service. It also supports the functions needed to generate new directories and add new files to existing directories.
    
- **Interface Operations:** The directory service provides the following operations:
    
    - `Lookup(Dir, Name) -> FileId`: Locates the text name in the directory and returns the relevant UFID. If the name is not in the directory, it throws an exception.
        
    - `AddName(Dir, Name, File)`: If the name is not present, it adds the _(Name, File)_ mapping to the directory and updates the file’s attribute record. It throws an exception if the name already exists.
        
    - `UnName(Dir, Name)`: If the name is in the directory, the entry containing the Name is removed. If not, it throws an exception.
        
    - `GetNames(Dir, Pattern) -> NameSeq`: Returns all the text names in the directory that match a specific regular expression pattern.
        

#### **3. The Client Module**

- **Responsibility:** The client module runs on each individual client computer. It integrates both the flat file service and the directory service, providing them as a single, unified Application Programming Interface (API) to the application programs.
    

#### **4. Access Control and Security**

- In distributed implementations, access rights checks must be performed strictly at the server because the server's RPC interface is otherwise an unprotected point of access to the files.
    
- An access check is made whenever a file name is converted to a UFID.
    
- A user identity is submitted with every single client request, and the server performs access checks for every file operation to ensure security.
    

#### **5. File Groups**

- A file group is a collection of files that can be located on any server or moved between servers while maintaining the exact same names.
    
- This concept helps significantly with distributing the load of file serving between several different servers.
    
- File groups have identifiers which must be globally unique throughout the entire open system.
