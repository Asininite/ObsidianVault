**Q1. What are the advantages of using distributed shared memory? [Part B, Q17(a) in May 2024 QP & Model QP Q8]**

**Answer:** DSM combines the best features of shared-memory programming with distributed-memory hardware. Its primary advantages include:

1. **Simpler Programming Model:** It hides the complexity of network communication. Programmers do not need to write explicit message-passing commands, making it much easier to write, understand, and debug distributed applications.
    
2. **Massive Virtual Memory Space:** By logically combining the physical memory of multiple independent computers across the network, DSM provides an enormous virtual address space that would be impossible or vastly expensive to build on a single machine.
    
3. **Data Portability and Transparency:** It provides data access transparency. Processes can access data in the shared space without needing to know which physical machine actually holds that data.
    
4. **Simplified Data Structures:** Passing complex data structures (like linked lists or massive trees) by reference is natural in DSM. In a message-passing system, the entire structure would need to be painfully packed, sent over the network, and unpacked.
    
5. **Cost-Effective:** It is much cheaper to network dozens of standard, off-the-shelf computers and use DSM than it is to buy a single, custom-built supercomputer with massive physical shared memory.

**Q2. Discuss the issues in implementing distributed shared memory / List the disadvantages of DSM. [Part B, Q18(a) in June 2023 QP]**

**Answer:** While DSM greatly simplifies programming, the abstraction introduces significant underlying challenges:

1. **Performance Overhead (Slower Access):** Because the memory is not physically shared, fetching a piece of data that resides on a different node requires network communication. This network latency makes DSM significantly slower than local physical memory access.
    
2. **Complex Consistency Management:** To speed things up, DSM often caches copies of the same data on different nodes. Keeping all these copies perfectly synchronized (maintaining consistency) when updates occur is mathematically complex and requires strict protocols.
    
3. **Thrashing:** If two or more nodes repeatedly try to write to the exact same block of data at the same time, the data block might constantly bounce back and forth across the network. This consumes massive bandwidth and grinds the system to a halt.
    
4. **Programmer Awareness:** While the basic concept is simple, achieving _good_ performance requires programmers to learn special rules and use specific synchronization tools to avoid massive network bottlenecks.
