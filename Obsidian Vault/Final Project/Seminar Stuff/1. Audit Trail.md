##  Formal Definition (from the paper and NIST):
> An **audit trail** is a **time-ordered log** of system activities that can be used to **recreate and review events and actions**, especially those related to **security**, **data integrity**, or **compliance**.

## Components of an Audit Trail:
1. **Event ID** – Unique identifier for the event.
2. **Timestamp** – When the event occurred.
3. **Actor/User** – Who performed the action.
4. **Action** – What was done (e.g., file edited, transaction made).
5. **Object** – What was affected (e.g., which file, which account).
6. **Outcome** – Result of the action (success/failure).

## What are Audit Trails in Cryptography?
In **cryptography and secure systems**, an **audit trail** is a **secure log** that records all actions or changes in a system in a way that:
1. **Cannot be tampered with**
2. Can be **independently verified**
3. Provides **cryptographic assurance** of integrity, time, and origin

These are used in:
- Financial transactions
- Access logs
- Legal compliance systems
- Blockchain applications
- Secure messaging or storage systems
