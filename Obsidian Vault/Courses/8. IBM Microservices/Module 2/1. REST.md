# What is REST? (Representational State Transfer)

## 1. Introduction to REST

- **Definition:** REST stands for **Representational State Transfer**. It is an architectural style (not a strict protocol or software) that defines how applications should communicate with each other over a network.
    
- **The Microservices Standard:** REST APIs provide a flexible, lightweight way to integrate applications and have emerged as the absolute most common method for connecting the independent components in a microservices architecture.
    
- **Payload Format:** Data is typically sent and received in a simple, human-readable format like **JSON** (JavaScript Object Notation).
    

## 2. The Three Key Characteristics of REST

For an API to be classified as truly "RESTful," it must exhibit these three characteristics:

1. **HTTP-Driven:** It manages all requests and communication through standard HTTP protocols.
    
2. **Stateless, Client-Server Communication:** The client (frontend) and server (backend) are entirely separate, and the server retains no memory of past requests.
    
3. **Uniform Interface:** There is a standardized, consistent way to access and represent data components across the entire API.
    

## 3. How REST Communicates: HTTP and CRUD

REST APIs communicate via HTTP requests to perform standard database functions, commonly referred to as **CRUD** (Create, Read, Update, Delete).

REST maps these CRUD operations directly to standard HTTP methods:

- **POST (Create):** Used to create a brand new record (e.g., creating a new user account).
    
- **GET (Read/Retrieve):** Used to retrieve or fetch a record (e.g., getting the details of a specific product).
    
- **PUT (Update):** Used to update or modify an existing record (e.g., changing the price of a product).
    
- **DELETE (Delete):** Used to remove a record from the resource.
    

## 4. Deep Dive: Statelessness and Scalability

- **What "Stateless" Means:** In REST, every single request from the client to the server must contain **all** of the information necessary to understand and process that request.
    
- **No Server Memory:** The server cannot take advantage of any stored context or "session state" from previous interactions. Any session state (like knowing a user is logged in) must be kept entirely on the client side and sent with every request (e.g., sending an authentication token every time).
    
- **Why this enables Scalability:** Because the server doesn't need to remember who you are between requests, **any** available server instance can handle your next request. You don't have to be routed back to the specific server that handled your last action. This makes horizontal scaling (adding more servers) incredibly easy.
    

## 5. Deep Dive: The Uniform Interface and URIs

The main benefit of RESTful APIs is the uniform interface. No matter where a request originates (a mobile app, a web browser, or another microservice), the interface behaves exactly the same.

- **URIs (Uniform Resource Identifiers):** A REST API ensures that a specific piece of data belongs to only one strict, uniform address (URI).
    
    - _Example:_ If you want data for Product #105, the URI will always logically be something like `https://api.store.com/products/105`.
        
- **Complete Resources:** When you hit that URI, the resource returned should contain _every_ piece of information the client might need about that object (e.g., returning the product's name, price, description, and inventory status all at once).
    

## 6. Real-World Example: CEX.IO

The video highlights CEX.IO (a cryptocurrency exchange) as a prime example of a REST API in the wild.

- They provide developers with market data (like Bitcoin prices) via REST.
    
- They use a uniform, documented interface so developers know exactly what parameters to send and what responses they will get back.
    
- The data is exchanged in simple JSON format.
    
- Because REST is standard across the industry, developers can easily interact with this API using almost any programming language (JavaScript, Python, C#, Java, etc.).
    

## Quick Revision Questions & Answers

**1. What does REST stand for?**

- **Answer:** Representational State Transfer.
    

**2. What are the four primary HTTP methods used in REST, and what CRUD operations do they map to?**

- **Answer:** POST (Create), GET (Read), PUT (Update), and DELETE (Delete).
    

**3. What does it mean when we say a REST API is "stateless"?**

- **Answer:** It means the server does not store any memory or context of past requests. Every single request from the client must contain all the information the server needs to process it independently.
    

**4. Why does statelessness make a REST API highly scalable?**

- **Answer:** Because there is no stored session data on the server, an application can seamlessly add more servers to handle heavy traffic. Any server can process any incoming request without needing to know the user's past history.
    

**5. In a REST API, what is a URI?**

- **Answer:** A Uniform Resource Identifier. It is the specific, standardized address/endpoint used to access a single, distinct piece of data (like a specific product or user profile).
