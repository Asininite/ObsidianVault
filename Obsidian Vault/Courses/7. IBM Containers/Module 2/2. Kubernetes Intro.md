# Introduction to Kubernetes (K8s)

## 1. What is Kubernetes?

- **Definition:** An open-source system for automating the deployment, scaling, and management of containerized applications.
    
- **Industry Status:** The _de facto_ standard choice for container orchestration globally.
    
- **Origin & Maintenance:** Originally developed as a project by Google; currently maintained by the Cloud Native Computing Foundation (CNCF).
    
- **Portability:** Easily portable and functional across both cloud and on-premises environments.
    
- **Management Style:** Uses _declarative management_—you define the desired state, and Kubernetes automatically performs the operations required to achieve and maintain that state.
    
- **Evolution:** Grew as an extension of "Containers as a Service" to "Kubernetes as a Service".
    

## 2. What Kubernetes is NOT

To understand Kubernetes, it is important to know its boundaries.

- **NOT a Traditional PaaS:** It is not an all-inclusive Platform-as-a-Service.
    
- **NOT Rigid:** It is a highly flexible model supporting diverse workloads (stateless, stateful, and data processing), rather than being rigid or opinionated.
    
- **NOT a CI/CD Tool:** It does not provide built-in Continuous Integration/Continuous Deployment pipelines to build applications or deploy source code.
    
- **NOT a Monitoring Solution:** It does not prescribe specific logging, monitoring, or alerting solutions (organizations integrate third-party tools of their choice).
    
- **NOT a Service Provider:** It does not provide built-in middleware, databases, or other similar background services.
    

## 3. Core Kubernetes Concepts

- **Pods:** The smallest deployable compute object in Kubernetes. A higher-level abstraction used to run workloads. Each pod gets a unique IP address.
    
- **Services:** Expose applications running on sets of pods. A set of pods is unified under a single DNS name.
    
- **Storage:** Kubernetes supports both persistent (permanent) and temporary storage for pods.
    
- **Configuration:** The provisioning of resources for configuring pods.
    
- **Security:** Measures enforcing security for pod and API access across cloud-native workloads.
    
- **Policies:** Rules for groups of resources, ensuring pods are properly matched to nodes so the `kubelet` can find and run them.
    
- **Scheduling and Eviction:** The process of running pods, or proactively terminating pods on nodes that are starved for resources.
    
- **Preemption (Prioritization):** Terminates lower-priority pods to free up resources so higher-priority pods can be scheduled and run.
    
- **Cluster Administration:** The underlying details and settings required to create, manage, or administer a Kubernetes cluster.
    

## 4. Kubernetes Capabilities

- **Automated Rollouts & Rollbacks:** Automatically rolls out changes to applications/configurations, monitors health, and rolls back if something goes wrong.
    
- **Storage Orchestration:** Automatically mounts a chosen storage system (local, network, or public cloud storage).
    
- **Horizontal Scaling:** Scales workloads up or down automatically based on metrics (like CPU usage) or via manual commands.
    
- **Automated Bin Packing:** Automatically places containers based on their specific resource requirements without sacrificing high availability, which increases utilization and saves costs.
    
- **Secret & Configuration Management:** Securely manages sensitive data (passwords, OAuth tokens, SSH keys) and updates them without needing to rebuild container images.
    
- **Networking:** Fully supports both IPv4 and IPv6 dual-stack for pods and services.
    
- **Workload Management:** Easily manages batch execution and continuous integration workloads.
    
- **Self-Healing:** Automatically detects, restarts, replaces, or removes failing or unresponsive containers.
    
- **Service Discovery & Load Balancing:** Locates pods using IP addresses or DNS names and load-balances network traffic to ensure high performance and availability.
    
- **Extensibility:** Designed to allow users to add custom features to a cluster without modifying the core Kubernetes source code.
    

## 5. The Kubernetes Ecosystem

The ecosystem is massive, rapidly growing, and includes a huge collection of products, services, and providers:

- **Leading Public Clouds:** AWS, Google, IBM, Prisma.
    
- **Framework Providers:** Docker, Cloud Foundry, Mesosphere, Red Hat, SUSE, VMware.
    
- **Management Providers:** CloudSoft, Digital Ocean, Loodse, Supergiant, Tectonic, Turbonomic, Weaveworks.
    
- **Tool Providers:** Aspen Mesh, Bitnami, Cloud 66, JFrog, Univa.
    
- **Monitoring & Logging:** Datadog, Dynatrace, Grafana, Iguazio, New Relic, SignalFx, Sumo Logic, Sysdig.
    
- **Security:** Alcide, Aqua, Black Duck, Cilium, Guardicore, Twistlock, Yubico.
    
- **Load Balancing:** Avi Networks, NGINX, VMware.
