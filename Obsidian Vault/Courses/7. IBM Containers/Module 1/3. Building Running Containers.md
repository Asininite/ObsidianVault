# Building and Running Containers

## 1. The Container Development Lifecycle

The process of getting an application to run inside a Docker container follows a strict three-step lifecycle:

1. **Create a Dockerfile:** Write a text file containing the instructions needed to build your application environment.
    
2. **Create a Container Image:** Use the Dockerfile to "build" a static, immutable container image.
    
3. **Create a Running Container:** Use that container image to "run" an active container instance.
    

## 2. The Dockerfile

A Dockerfile is a simple text document that contains all the commands a user could call on the command line to assemble an image.

- **`FROM`**: This command defines the **base image**. Every Dockerfile must start with a `FROM` command (e.g., `FROM python:3.9` or `FROM ubuntu:latest`). It acts as the foundation of your container.
    
- **`CMD`**: This command specifies the default instruction that should execute when a container starts (e.g., printing "Hello World" to the terminal, or starting a web server).
    

## 3. Key Docker Commands

### A. Building the Image (`docker build`)

- **Purpose:** Used to create container images from a Dockerfile.
    
- **Syntax:** `docker build -t <repository>:<tag> .`
    
- **Components:**
    
    - **Tag/Repository/Version:** You name your image using the `-t` flag (e.g., `-t my-app:v1`).
        
    - **Current Directory (`.`):** The period at the end tells Docker to look in the current directory for the Dockerfile and the "build context" (your application files).
        
- **Expected Output:** You will see messages like "sending build context to Docker Daemon", "successfully built `<image_id>`", and "successfully tagged `my-app:v1`".
    

### B. Verifying the Image (`docker images`)

- **Purpose:** Lists all the container images currently stored locally on your machine.
    
- **What it displays:**
    
    - **Repository:** The name of the image (e.g., `my-app`).
        
    - **Tag:** The version (e.g., `v1`).
        
    - **Image ID:** A unique alphanumeric identifier.
        
    - **Creation Date:** When it was built.
        
    - **Size:** Total disk space the image consumes.
        

### C. Running the Container (`docker run`)

- **Purpose:** Creates and runs a live container instance from a static image.
    
- **Syntax:** `docker run my-app:v1`
    
- **Result:** The application executes the instruction defined in the `CMD` step of the Dockerfile (e.g., printing "Hello World" to the terminal).
    

### D. Verifying Running Containers (`docker ps -a`)

- **Purpose:** Displays the details and status of your containers.
    
- _(Note: The transcript mentions the "PSA command", which is a phonetic misinterpretation of `docker ps -a`)_.
    
    - `docker ps`: Shows only currently running containers.
        
    - `docker ps -a`: Shows **all** containers (both running and stopped).
        

### E. Interacting with Registries (`docker push` & `docker pull`)

A container registry (like Docker Hub or IBM Cloud Container Registry) is a centralized storage location for your images.

- **`docker pull`**: Retrieves (downloads) an existing image from a configured remote registry to your local machine.
    
	- **`docker push`**: Stores (uploads) your locally built image into a remote registry so others (or your deployment servers) can access it.
