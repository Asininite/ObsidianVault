
# Introduction to Docker Objects

## 1. Overview of Docker Objects

Docker utilizes several core objects to build, run, and manage applications:

- **Dockerfile:** A text file containing instructions to build an image.
    
- **Images:** Read-only templates used to create containers.
    
- **Containers:** Runnable, isolated instances of images.
    
- **Networks:** Used to isolate and manage container communications.
    
- **Storage Volumes:** Used to persist data outside the container's lifecycle.
    
- **Plugins/Add-ons:** Extensions (like storage plugins) that add specific capabilities.
    

## 2. Essential Dockerfile Instructions

A Dockerfile can be created in any text editor and relies on specific instructions to assemble an image.

- **`FROM`**:
    
    - **Mandatory:** Every Dockerfile _must_ begin with this instruction.
        
    - **Function:** Defines the base image (e.g., an OS like Ubuntu, or a language environment like Node.js or Go from a public repository).
        
- **`RUN`**:
    
    - **Function:** Executes specific commands during the image build process (e.g., installing packages).
        
- **`CMD`**:
    
    - **Function:** Defines the default command that executes when the container starts.
        
    - **Rule:** A Dockerfile should only have _one_ `CMD` instruction. If multiple are provided, **only the last `CMD` instruction will take effect**.
        

## 3. Docker Images & Layering

- **Definition:** A read-only template containing instructions for creating a Docker container.
    
- **The Layering System:**
    
    - Every instruction in a Dockerfile creates a new, distinct "layer" in the image.
        
    - **Caching & Efficiency:** When you modify a Dockerfile and rebuild the image, the Docker engine only rebuilds the layers that have changed.
        
    - **Resource Saving:** Different images can share identical layers, which massively saves local disk space and reduces network bandwidth when pulling/pushing images.
        

## 4. Docker Containers

- **Definition:** A runnable instance of a Docker image.
    
- **The Writable Layer:** Because containers need to be modified while running (they are not immutable like images), Docker places a **writable container layer** on top of the image's read-only layers when a container is instantiated.
    
- **Management:** You can create, start, stop, or delete containers using the Docker API or CLI.
    
- **Capabilities:** * Can be connected to multiple networks.
    
    - Can have storage attached to them.
        
    - Can be converted into a brand-new image based on their current state.
        
- **Isolation:** Containers are strictly isolated from the host machine and from each other.
    

## 5. Image Naming Convention

Docker image names follow a unique, strict three-part format: `[hostname]/[repository]:[tag]`

- **Hostname:** Identifies the specific image registry where the image is stored.
    
    - _Example:_ `docker.io` refers to the official Docker Hub registry. (Note: The Docker CLI allows you to exclude `docker.io` as it defaults to Docker Hub).
        
- **Repository:** A grouping of related container images.
    
    - _Example:_ `ubuntu` indicates the official Ubuntu images.
        
- **Tag:** Provides information about a specific version or variant of the image.
    
    - _Example:_ `18.04` represents that specific version of Ubuntu.
        
- **Full Example:** `docker.io/ubuntu:18.04`
    

## 6. Networks, Storage, and Plugins

- **Networks:** Used to isolate and secure communications between containers.
    
- **Storage (Volumes and Bind Mounts):** * **The Problem:** By default, any data generated inside a container is lost when the container stops or is deleted.
    
    - **The Solution:** Docker uses **Volumes** and **Bind Mounts** to persist data independently of the container's lifecycle.
        
- **Plugins:** Enhance Docker's core functionality (e.g., Storage Plugins allow Docker to connect directly to external/third-party storage platforms).
