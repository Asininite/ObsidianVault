
|Term|Definition|
|---|---|
|**Cluster Autoscaler**|Also known as CA. An API resource that autoscales the cluster itself, increasing and decreasing the number of available nodes that pods can run on.|
|**Config Map**|An API object used to store non-confidential data in key-value pairs. Pods can consume ConfigMaps as environment variables, command-line arguments, or as configuration files in a volume.|
|**Horizontal Pod Autoscaler**|Also known as:HPA An API resource that automatically scales the number of Pod replicas based on targeted CPU utilization or custom metric targets.|
|**Linguistic Analysis**|Detects the tone in a given text.|
|**IBM Cloud catalog**|provides various Services that range from visual recognition to natural language processing and creating chatbots.|
|**Persistent Volume**|An API object that represents a piece of storage in the cluster. Available as a general, pluggable resource that persists beyond the lifecycle of any individual Pod.|
|**Persistent Volume Claim**|Claims storage resources defined in a PersistentVolume so that it can be mounted as a volume in a container.|
|**Rolling Updates**|Provide a way to roll out application changes in an automated and controlled fashion throughout your pods. Rolling updates work with pod templates such as deployments. Rolling updates allow for rollback if something goes wrong.|
|**Secrets**|Stores sensitive information, such as passwords, OAuth tokens, and ssh keys.|
|**Service binding**|is the process needed to consume external Services or backing Services, including REST APIs, databases, and event buses in your applications.|
|**Tone Analyzer Service**|is used for explaining service binding. This IBM Cloud Service uses linguistic analysis to detect tone in a given text.|
|**Vertical Pod Autoscaler also known as VPA**|An API resource that adds resources to an existing machine. A VPA lets you scale a service vertically within a cluster.|
|**Volume**|A directory containing data, accessible to multiple containers in a Pod.|
|**Volume Mount**|entails mounting of the declared volume into a container in the same Pod.|
|**Volume Plugin**|A Volume Plugin enables integration of storage within a Pod.|
### **Part 1: Your Specific Quiz Doubts**

**1. Which rolling update types ensure 100% app availability?**

- **Answer:** One-at-a-time updates and rollbacks ensure 100% app availability.
    

**2. How do you create a ReplicaSet from scratch?**

- **Answer:** Apply a YAML file with the 'kind' attribute set to 'ReplicaSet'.
    

**3. What are three ways to create a Secret?**

- **Answer:** 1. By using a string literal
    
    2. By using environment variables
    
    3. By using volume mounts
    

**4. What are three ways to create a ConfigMap?**

- **Answer:** 1. By using an existing property or 'key' = 'value' file
    
    2. By using string literals
    
    3. By providing a ConfigMap YAML descriptor file
    

### **Part 2: Module Concept Revision Questions**

#### **Kubernetes Architecture**

**5. What is the fundamental difference in responsibilities between the Control Plane and the Worker Plane?**

- **Answer:** The Control Plane makes global decisions and manages the cluster's state. The Worker Plane contains the actual machines that run the user's containerized applications.
    

**6. Which control plane component acts as the single source of truth for the cluster's desired state?**

- **Answer:** `etcd`.
    

**7. How does the `kube-scheduler` decide where to place a newly created pod?**

- **Answer:** It evaluates available hardware resources, configuration options, and scheduling principles to find the optimal node.
    

**8. What is the primary role of the `kubelet` on a worker node?**

- **Answer:** It communicates with the control plane to receive pod specs, ensures containers are running, and reports health status back to the control plane.
    

#### **Kubernetes Objects (Part 1 & 2)**

**9. What are the two main fields of a Kubernetes object?**

- **Answer:** `Object Spec` (desired state, provided by user) and `Status` (current state, provided by Kubernetes).
    

**10. Why would an organization use multiple Namespaces in a single cluster?**

- **Answer:** To safely isolate groups of resources, allowing multiple teams/projects to share a cluster and save costs.
    

**11. Which Kubernetes object is best suited for managing a stateless application?**

- **Answer:** A Deployment.
    

**12. Why do we need Services in Kubernetes if Pods already have their own IP addresses?**

- **Answer:** Pod IPs change when they are destroyed/recreated. Services provide a stable, persistent IP address to reliably access those Pods.
    

**13. Which Service type is the default, and what is its primary limitation?**

- **Answer:** ClusterIP. It is only accessible from _within_ the cluster.
    

**14. If you needed to deploy a log collection agent on every single active node, which object would you use?**

- **Answer:** A DaemonSet.
    

**15. What are the two main guarantees a StatefulSet provides that a standard Deployment does not?**

- **Answer:** Ordering and uniqueness of Pods (sticky identity and persistent storage).
    

#### **Using Kubectl & Antipatterns**

**16. What are the four components of a standard Kubectl command, in order?**

- **Answer:** Command, Type, Name, Flags.
    

**17. Which Kubectl command type is considered the best practice for production environments?**

- **Answer:** Declarative Object Configuration (using files to define a single source of truth).
    

**18. Why is using the `:latest` tag for container images considered dangerous in production?**

- **Answer:** It makes it impossible to know exactly which version is running, leading to unpredictable deployments and difficult rollbacks.
    

**19. What is "configuration drift" and which anti-pattern causes it?**

- **Answer:** When the live environment no longer matches source code, caused by making ad-hoc manual changes directly to the cluster (e.g., `kubectl edit`).
    

#### **ReplicaSets & Deployments**

**20. How does a ReplicaSet know which pods it is supposed to manage?**

- **Answer:** It uses label selectors.
    

**21. Why is it considered a bad practice to create a ReplicaSet directly?**

- **Answer:** Deployments automatically manage ReplicaSets for you while offering superior features like rolling updates and rollbacks.
    

**22. Which deployment strategy introduces application downtime by design?**

- **Answer:** The Recreate strategy (shuts down all old pods before starting new ones).
    

**23. What is the primary difference between a Blue/Green strategy and a Rolling strategy?**

- **Answer:** Blue/Green requires spinning up a duplicate environment to switch traffic instantly. Rolling replaces pods one-by-one within the existing infrastructure.
    

**24. How does the Shadow strategy allow you to test production traffic safely?**

- **Answer:** It duplicates live user requests to the new version, but suppresses/ignores the responses so the user only sees the stable version.
    

#### **Rolling Updates & Configurations**

**25. What two probes must be added to a deployment to prepare it for a rolling update?**

- **Answer:** Liveness probes and Readiness probes.
    

**26. If you want to absolutely guarantee zero downtime during a rolling update, what must `maxUnavailable` be set to?**

- **Answer:** `0`.
    

**27. Why is it a bad practice to hard-code configuration variables directly into your application's source code?**

- **Answer:** Changes would require editing source code, rebuilding the image, and full redeployment. ConfigMaps/Secrets decouple this.
    

**28. What is the maximum data size limit for a single Kubernetes ConfigMap?**

- **Answer:** 1 Megabyte (1MB).
    

**29. Why must you run `kubectl rollout restart deployment` after updating a ConfigMap?**

- **Answer:** If injected as environment variables, the new values are only read when a container starts. A restart forces the pods to reload the new data.
    

#### **Service Binding & Autoscaling**

**30. What native Kubernetes object is automatically created to store external service credentials during Service Binding?**

- **Answer:** A Secret.
    

**31. In what format are service binding credentials stored?**

- **Answer:** Base64 encoded in JSON format.
    

**32. What is the difference between `kubectl scale` and `kubectl autoscale`?**

- **Answer:** `scale` requires manual intervention to set a hard number. `autoscale` creates an HPA that dynamically adjusts replicas based on real-time metrics.
    

**33. What critical configuration must be added to a `deployment.yaml` before a Horizontal Pod Autoscaler (HPA) can function?**

- **Answer:** Resource requests and limits (e.g., CPU limits). Without them, HPA cannot calculate utilization percentages.
