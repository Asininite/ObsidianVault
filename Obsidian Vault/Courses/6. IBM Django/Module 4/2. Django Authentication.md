# Django Authentication and Authorization

## 1. Core Concepts: Authentication vs. Authorization

- **Authentication (Who are you?):** * The process of validating a user's identity.
    
    - Uses credentials like username/password, one-time passcodes (SMS/email), Single Sign-On (SSO), or biometrics.
        
- **Authorization (What are you allowed to do?):** * Happens _after_ authentication.
    
    - The process of checking if the authenticated user has the correct permissions to access specific resources (e.g., viewing a course, deleting a database record).
        

## 2. The Built-in User Model

- **Function:** Django provides a built-in `User` model to handle authentication and store basic information (username, password, email).
    
- **Interactivity:** It works seamlessly with `Group` and `Permission` models to handle authorization.
    
- **Extensibility:** Developers can extend the base `User` model to define application-specific personas (e.g., creating `Instructor` or `Learner` models that inherit from the base `User`).
    

## 3. Implementing Login and Sessions

The login process involves an HTML form, a view to process the request, and session management.

### A. The Login Form (HTML)

- Uses a standard `<form>` making a `POST` request to the backend.
    
- Requires input fields for `username` and `password` (using `type="password"` to mask the characters).
    
- _(Extra Info: Just like other POST forms, it must include `{% csrf_token %}` for security)._
    

### B. The Login View (Python)

To log a user in, Django provides two essential functions: `authenticate()` and `login()`.

1. **`authenticate(request, username, password)`:**
    
    - Verifies the credentials against the database.
        
    - Returns a valid `User` object if they match.
        
    - Returns `None` if the credentials are invalid.
        
2. **`login(request, user)`:**
    
    - Actually logs the user in by creating a session.
        

### C. Sessions and Cookies

- **How it works:** Because HTTP is stateless, Django uses sessions to remember that a user is logged in as they navigate from page to page.
    
- **Server-Side (Session):** Once logged in, Django creates a unique session ID. It queries the user's info (like User ID) and stores this stateful data in a session dictionary on the server.
    
- **Client-Side (Cookie):** The server sends the session ID to the user's browser, which stores it in a COOKIE.
    
- **Validation:** * If authenticated: `request.COOKIES` contains a valid session ID, and `request.session` contains user data.
    
    - If _not_ authenticated: Session ID is `None`, and the session dictionary is empty.
        

## 4. Implementing Registration and Logout

### A. Registration View

- Very similar to the login view: it receives a `POST` request with a username and password from an HTML form.
    
- **Creation:** Uses the User model manager's built-in `create_user()` method to safely create and hash the password for the new user.
    
    - _Example:_ `User.objects.create_user(username=username, password=password)`
        
- Once created, the user can be immediately logged in and redirected to the homepage.
    

### B. Logout View

- Simply call Django's built-in `logout(request)` function.
    
- This completely flushes the session data and deletes the session cookie.
    

## 5. Authorization: Permissions and Groups

Authorization is managed using three main models: `User`, `Permission`, and `Group`. _(Extra info: These are imported from `django.contrib.auth.models`)_.

### A. Permissions

- The `Permission` model has a **many-to-many** relationship with the `User` model.
    
- By default, whenever you create a new Model in Django (e.g., `Course`), Django automatically creates four default permissions for it:
    
    1. **Add** (Can add course)
        
    2. **Change** (Can change/edit course)
        
    3. **Delete** (Can delete course)
        
    4. **View** (Can view course)
        

### B. Groups

- **Function:** Provides a convenient way to manage sets of users who all share the exact same permissions.
    
- **Workflow:** System admins create roles (Groups) and assign specific permissions to those groups.
    
    - _Example:_ Create an "Instructors" group and assign it the Add, Change, Delete, and View permissions for the `Course` model.
        
    - Create a "Learners" group and assign it _only_ the View permission.
        
- **Efficiency:** When a new instructor is hired, you simply add their `User` account to the "Instructors" group, and they automatically inherit all the associated permissions without needing manual configuration.
    
- **Management:** The easiest way to manage Groups and Permissions is through the built-in Django Admin site, though it can also be done programmatically using Django's APIs.

## 3. Displaying User Information in Templates

When a user logs in, Django automatically queries the `user` object based on the `session_id` and makes it globally available to your templates.

- **Checking Authentication Status:** Use the `{% if user.is_authenticated %}` tag to show different UI elements to logged-in users versus anonymous visitors.
    
- **Accessing User Attributes:** You can directly access user data using dot notation (e.g., `{{ user.username }}`).
    

**Example (HTML):**

```
{% if user.is_authenticated %}
    <p>Welcome, {{ user.first_name }} {{ user.last_name }} ({{ user.username }})!</p>
    <a href="{% url 'onlinecourse:logout' %}">Logout</a>
{% else %}
    <p>Welcome, Visitor!</p>
    <a href="{% url 'onlinecourse:login' %}">Login</a>
{% endif %}
```

## 4. Implementing Login and Sessions

The login process involves an HTML form, a view to process the request, and session management.

### A. The Login Form (HTML)

- Uses a standard `<form>` making a `POST` request to the backend view.
    
- Requires input fields for `username` and `password` (`type="password"` masks the text).
    
- **Crucial:** Must include `{% csrf_token %}` to protect against Cross-Site Request Forgery.
    

```
<form action="{% url 'onlinecourse:login' %}" method="post">
    {% csrf_token %}
    <label for="username"><b>User Name</b></label>
    <input type="text" name="username" required>
    
    <label for="psw"><b>Password</b></label>
    <input type="password" name="psw" required>
    
    <button type="submit">Login</button>
</form>
```

### B. The Login View (Python)

To log a user in, Django provides two essential functions from `django.contrib.auth`: `authenticate()` and `login()`.

```
from django.contrib.auth import authenticate, login
from django.shortcuts import render, redirect

def login_request(request):
    if request.method == "POST":
        # 1. Get credentials from request payload
        username = request.POST['username']
        password = request.POST['psw']
        
        # 2. Authenticate the user against the database
        user = authenticate(username=username, password=password)
        
        if user is not None:
            # 3. If valid, create a session and log them in
            login(request, user)
            return redirect('onlinecourse:popular_course_list')
        else:
            # If invalid, re-render the login page (could add error messages here)
            return render(request, 'onlinecourse/user_login.html')
    else:
        return render(request, 'onlinecourse/user_login.html')
```

### C. Sessions and Cookies (Behind the Scenes)

- **Server-Side (Session):** Once `login(request, user)` is called, Django creates a unique session ID, queries the user's ID, and stores this stateful data in a session dictionary on the server.
    
- **Client-Side (Cookie):** The server sends the session ID to the browser, which stores it in a COOKIE.
    
- As the user browses, Django reads this cookie, looks up the session, and attaches the `User` object to the `request` automatically.
    

## 5. Implementing Logout

Logging out is incredibly simple using Django's built-in `logout()` method. It flushes the session data on the server and deletes the session cookie in the user's browser.

**The Logout View (Python):**

```
from django.contrib.auth import logout
from django.shortcuts import redirect

def logout_request(request):
    # Pass the request object to the logout function
    logout(request)
    # Redirect back to the main page
    return redirect('onlinecourse:popular_course_list')
```

## 6. Implementing User Registration

### A. The Registration Form (HTML)

Very similar to the login form, but it collects more information (like First Name and Last Name) to create a robust profile.

```
<form action="{% url 'onlinecourse:registration' %}" method="post">
    {% csrf_token %}
    <input type="text" name="username" placeholder="User Name" required>
    <input type="text" name="firstname" placeholder="First Name" required>
    <input type="text" name="lastname" placeholder="Last Name" required>
    <input type="password" name="psw" placeholder="Password" required>
    <button type="submit">Sign Up</button>
</form>
```

### B. The Registration View (Python)

The registration view extracts the submitted data, ensures the username doesn't already exist, creates the new user securely, and immediately logs them in.

```
from django.contrib.auth.models import User
from django.contrib.auth import login
from django.shortcuts import render, redirect

def registration_request(request):
    if request.method == 'POST':
        # 1. Extract data from POST request
        username = request.POST['username']
        password = request.POST['psw']
        first_name = request.POST['firstname']
        last_name = request.POST['lastname']
        
        # 2. Check if the user already exists to prevent duplicate errors
        try:
            User.objects.get(username=username)
            user_exist = True
        except User.DoesNotExist:
            user_exist = False
            
        if not user_exist:
            # 3. Safely create the user (create_user automatically hashes the password)
            user = User.objects.create_user(
                username=username, 
                first_name=first_name, 
                last_name=last_name,
                password=password
            )
            # 4. Immediately log the new user in
            login(request, user)
            return redirect("onlinecourse:popular_course_list")
        else:
            # Re-render form (Ideally with a "Username taken" error)
            return render(request, 'onlinecourse/user_registration.html')
    else:
        return render(request, 'onlinecourse/user_registration.html')
```
