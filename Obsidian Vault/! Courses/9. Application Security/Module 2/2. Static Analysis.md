# Static Analysis and SAST

## 1. What is Static Analysis?
*   **Definition:** Static analysis is a debugging method that automatically inspects source code or runtime binaries to help detect common vulnerabilities *before* the code is executed.
*   **Why is it "Static"?** The tools examine the code statically on the file system; the code is analyzed without actually running or executing the program.
*   **SAST (Static Application Security Testing):** This is the specific application of static analysis for security purposes. It examines source code to identify security flaws that would make an application vulnerable to attack.
*   **Flexibility:** Some SAST solutions provide APIs for easy DevOps integration and, crucially, **do not require the code to be fully complete** to begin scanning.

## 2. Static Analysis in the SDLC
*   **Timing:** Static code analysis takes place very early in the software development lifecycle (SDLC), long before formal software testing begins.
*   **DevOps Integration:** In a DevOps enterprise, static analysis occurs during the **Develop** stage.
*   **The Feedback Loop:** Integrating SAST during the Develop stage establishes an automatic feedback loop. Developers are made aware of coding issues almost immediately after writing the code, making it much simpler (and cheaper) to resolve them.

## 3. The Three Significant Benefits of Static Analysis
While a thorough static scan can take a long time to complete, the best tools offer three major advantages over manual review:

### A. Depth
*   Manual testing cannot physically cover every single conceivable avenue or path of code execution. 
*   A static code analyzer has the depth to cover almost all possible execution paths. It verifies the code against predefined criteria, providing an in-depth analysis of exactly where potential problems might exist.

### B. Speed (and Cost Efficiency)
*   Automated tools scan code exponentially faster than manual human analyzers.
*   Because it identifies issues early and pinpoints the *exact location* of the problem in the code, developers can correct issues much more quickly. 
*   **The Golden Rule:** Code problems found early in the Develop stage are significantly less expensive to fix than bugs found in production.

### C. Accuracy
*   Automated static analysis tools provide a much higher degree of accuracy than human review.
*   Manual reviews require the reviewer to have a massive, constantly updated personal knowledge of all possible vulnerabilities. Automated scanning leverages deep, continuously updated databases of the latest vulnerabilities to examine every single line of code for potential errors.

## Quick Revision Questions & Answers

**1. Why is the process called "Static" analysis?**
*   **Answer:** Because the tools examine the raw source code on the file system; the code is analyzed without being run or executed.

**2. At what specific stage of the DevOps pipeline does static analysis typically occur?**
*   **Answer:** During the **Develop** stage (early in the SDLC, before formal testing begins).

**3. What does SAST stand for?**
*   **Answer:** Static Application Security Testing.

**4. Why is discovering a vulnerability via static analysis considered highly cost-effective?**
*   **Answer:** Because it catches the bug during the development phase. Finding and fixing a problem while the developer is actively writing the code is drastically cheaper and faster than discovering the bug after the software has been deployed to production.

**5. How does the "Accuracy" of an automated static analysis tool compare to manual human review?**
*   **Answer:** Automated tools are more accurate because they examine every single line of code without fatigue and leverage massive, constantly updated databases of vulnerabilities, whereas a human reviewer relies solely on their own personal, limited knowledge.
