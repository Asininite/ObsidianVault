# Introduction to the OWASP Top 10

## 1. What is OWASP?
*   **Definition:** The **Open Web Application Security Project (OWASP)** is a non-profit foundation formed in 2003 that focuses on software security.
*   **The OWASP Top 10:** A widely recognized report that identifies the most critical software security vulnerability concerns. It is considered the *de facto* industry standard for web application security.
*   **Development Process:** It is a consensus-based list compiled from data provided by the core team, security analysts, security organizations, and other experts globally.

---

## 2. The 2021 OWASP Top 10
These represent the most critical vulnerabilities found in web applications as of the 2021 report:

1.  **Broken Access Control:** Failures that allow unauthorized access, jeopardizing data integrity and disclosure.
2.  **Cryptographic Failures:** Issues related to data exposure (formerly known as "Sensitive Data Exposure").
3.  **Injection:** Flaws involving hostile data, unsafe queries, and improper command execution (e.g., SQL Injection).
4.  **Insecure Design:** Weaknesses and flaws in the control designs of the application.
5.  **Security Misconfiguration:** Features that are incorrectly enabled, insecure default settings, or mismanaged configurations.
6.  **Vulnerable and Outdated Components:** Using libraries, frameworks, or dependencies that have known security flaws or version compatibility issues.
7.  **Identification and Authentication Failures:** Password issues, credential stuffing (automated attacks), and flaws in session identifier management.
8.  **Software and Data Integrity Failures:** Vulnerabilities arising from untrusted sources or integrity violations (e.g., CI/CD pipeline compromises).
9.  **Security Logging and Monitoring Failures:** Inability to detect, report, or respond to active security breaches.
10. **Server-Side Request Forgery (SSRF):** Vulnerabilities resulting from improper URL validation when a server makes requests to other resources.

---

## 3. Developing the List (The 5-Step Process)
OWASP uses a rigorous data-driven methodology to create the list:
1.  **Plan:** Establish a schedule and publish a call for security data.
2.  **Survey:** Determine survey content and request industry participation.
3.  **Analyze:** Collect, normalize, and analyze the submitted security data.
4.  **Draft:** Determine eight categories based on the data and two based on the industry survey. Release this draft for public review and incorporate feedback.
5.  **Consensus:** Reach a final consensus and release the official OWASP Top 10.

## Quick Revision Questions & Answers

**1. What is the difference between "Broken Access Control" and "Identification and Authentication Failures"?**
*   **Answer:** Identification/Authentication is about *who* you are (logging in correctly). Broken Access Control is about *what you are allowed to do* once you are logged in.

**2. Why does OWASP encourage developers to contribute data?**
*   **Answer:** Because the Top 10 is built on consensus and real-world data. Developer feedback helps the list stay accurate to current, modern security threats.

**3. What is the purpose of the "Security Logging and Monitoring Failures" category?**
*   **Answer:** It highlights the risk that, even if an attack happens, the organization might never know about it because they failed to properly log or monitor their systems.

**4. Where in the SDLC should you use the OWASP Top 10?**
*   **Answer:** You should use it as a standard check throughout the lifecycle—from identifying risks during design to securing your code during development, all the way to pre-deployment.

**5. How many categories are derived from data versus the industry survey in the OWASP Top 10 methodology?**
*   **Answer:** Eight categories are derived from the raw data analysis, and two categories are determined by the industry survey.
