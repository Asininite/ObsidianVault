# SQL Injections

## 1. What is an SQL Injection?
*   **Definition:** An SQL injection (pronounced "sequel") is a severe security attack that involves passing a malicious string input to exploit a database.
*   **How it Occurs:** It typically occurs when a web page requests user input (like a username or password field) and directly uses that raw input to query the database.
*   **The Mechanism:** The attacker enters specific SQL commands into the input field to modify the backend SQL statement. They often use set operations or alter `WHERE` clauses to force the database to return alternate, unauthorized results.

## 2. Four Pervasive Types of SQL Injection
1.  **SQL Manipulation** (The most common type)
2.  **Code Injection**
3.  **Function Call Injection**
4.  **Buffer Overflows**

## 3. Deep Dive: SQL Manipulation
SQL manipulation attacks modify an existing SQL statement using set operations. They primarily target two elements:
*   The `WHERE` clause.
*   The `UNION` statement (used by attackers to grab and combine data from different, unauthorized tables).

### The "Always TRUE" Exploit (WHERE Clause)
A common goal of SQL manipulation during user authentication is to force the `WHERE` clause to always evaluate to `TRUE`, effectively bypassing the password check entirely.

*   **Original Intended Query:**
    `SELECT * FROM users WHERE username = 'alice' and PASSWORD = 'mypassword';`
*   **The Attack:** The attacker inputs `'mypassword' or 'a'='a'` into the password field.
*   **The Resulting Compromised Query:**
    `SELECT * FROM users WHERE username = 'alice' and PASSWORD = 'mypassword' or 'a'='a';`
*   **Why it works:** Because the letter 'a' will *always* equal 'a', the `OR` condition evaluates to `TRUE`. The database ignores the fact that the password might be wrong and grants access anyway.

## 4. The Danger of String Concatenation
The transcript provides a Python example demonstrating why SQL injection is possible. The fundamental flaw is using **string concatenation** to build SQL queries.

### The Vulnerable Python Code Structure
```python
username = request.args.get("username")
password = request.args.get("password")

# DANGEROUS: Concatenating raw variables directly into the SQL string
sql = 'SELECT * FROM Users WHERE Name = ' + username + ' AND Password = ' + password
db.execute(sql)
```

# Other Types of SQL Injection Attacks

## 1. Code Injection
*   **Definition:** An attack that inserts entirely new SQL statements or database commands into an existing SQL statement.
*   **The Mechanism:** The attacker uses the semicolon `;` character. In SQL, a semicolon explicitly marks the end of one statement and the beginning of another. The database receives what it thinks is a single request but executes two (or more) separate commands sequentially.
*   **The Danger:** This is highly destructive. An attacker can use code injection to delete specific tables or drop the entire database.

### Code Injection Example
*   **Original Safe Code:** `BEGIN ENCRYPT_PASSWORD(‘alice’, ‘mypassword’); END;`
*   **The Attack:** The attacker inputs `‘mypassword’); DELETE FROM users WHERE upper (username) = upper (‘admin’);`
*   **The Resulting Compromised Query:** 
    `BEGIN ENCRYPT_PASSWORD (‘alice’, ‘mypassword’); DELETE FROM users WHERE upper (username) = upper (‘admin’); END;`
*   **Outcome:** The password is encrypted as expected, but immediately after, the database executes the hidden `DELETE` command and removes the admin user.

### Dropping Tables via Code Injection
*   **The Vulnerable Code:** `sql = 'SELECT * FROM users WHERE Name ="' + username + '" AND password ="' + password + '"'`
*   **The Attack:** The attacker inputs `" ; DROP TABLE Users; --` into the username field.
*   **The Resulting Compromised Query:**
    `SELECT * FROM Users WHERE Name = ""; DROP TABLE Users; -- AND password ="..."`
*   **How the syntax works:** 
    1.  The first `"` closes the string. 
    2.  The `;` ends the SELECT statement. 
    3.  `DROP TABLE Users;` executes as a brand new, destructive command. 
    4.  The `--` is the SQL comment character. It tells the interpreter to completely ignore the rest of the original query (the password check).

## 2. Function Call Injection
*   **Definition:** An attack that inserts a custom, malicious function call into a vulnerable SQL statement.
*   **The Mechanism:** Uses the double vertical bar `||`, which is the string concatenation character in SQL.
*   **The Danger:** Attackers can send database data to remote computers, change passwords, or perform sensitive database transactions by forcing the database to run specific functions.
*   **Example Outcome:** Instead of just returning a value, the query might secretly run `myappadmin.adduser('admin', 'newpass')`, granting the attacker a new admin account.

## 3. Buffer Overflows
*   **Definition:** Occurs when a program allocates more data in a temporary storage buffer than that buffer is physically designed to hold.
*   **The Danger:** This overflow can cause the database or program to crash entirely, or it can be used to execute malicious code.
*   **The Vulnerability:** Attackers target specific database functions (like `tz_offset`, `to_timestamp_tz`, or `bfilename`) that historically had buffer overflow vulnerabilities if the database software was left unpatched.

## 4. Preventing SQL Injection Attacks
To protect applications from all forms of SQL injection, implement the following measures:

1.  **Use Query Parameters (Parameterized Queries):**
    *   This is the most critical defense. Use placeholders (like `?`) instead of concatenating raw strings.
    *   *Safe Code Example:* `sql = "SELECT * FROM Users WHERE userid = ?;"` and then passing the `username` variable to the execution method safely: `db.execute(sql, username)`.
    *   *Why it works:* The SQL interpreter strictly treats the placeholder input as a literal string value, not as executable code. Even if an attacker types `DROP TABLE`, it is treated just as a username named "DROP TABLE", neutralizing the threat.
2.  **Server-Side Validation:** Always validate and sanitize untrusted data inputs on the server side, never rely solely on client-side (browser) validation.
3.  **Restrict User Privileges (PoLP):** Implement the Principle of Least Privilege. Ensure the database user account used by the application only has the absolute minimum rights (e.g., start with read-only access where possible) to limit damage if an injection succeeds.
4.  **Database Patching:** Keep your database software updated and patched to eliminate known vulnerabilities (like the buffer overflow exploits in certain functions).
5.  **Use DAST:** Perform Dynamic Application Security Testing to identify actively exploitable vulnerabilities when releasing new code to production.

## Quick Revision Questions & Answers

**1. In a Code Injection attack, what specific character does an attacker use to force the database to execute a second, hidden command?**
*   **Answer:** The semicolon (`;`).

**2. What does the double dash (`--`) signify in SQL syntax, and why do attackers use it during code injection?**
*   **Answer:** It is the SQL comment character. Attackers use it to "comment out" and effectively delete the remainder of the original, legitimate query so it doesn't cause syntax errors or interfere with their malicious payload.

**3. What is the primary purpose of a Function Call Injection attack?**
*   **Answer:** To force the database to execute a specific, potentially malicious custom function (like adding a new admin user or changing passwords) rather than just retrieving data.

**4. Why are Parameterized Queries (using placeholders like `?`) the best defense against SQL injection?**
*   **Answer:** Because they separate the SQL code from the data. The SQL interpreter strictly treats the placeholder input as a literal data string, meaning any malicious SQL commands typed by the attacker will not be executed.

**5. How can the Principle of Least Privilege mitigate the damage of an SQL injection attack?**
*   **Answer:** If the application's database account is restricted (e.g., having only read access), an attacker who successfully executes an injection won't have the required permissions to drop tables or delete the database.
