# SQL Injections

## 1. What is an SQL Injection?
*   **Definition:** An SQL injection (pronounced "sequel") is a severe security attack that involves passing a malicious string input to exploit a database.
*   **How it Occurs:** It typically occurs when a web page requests user input (like a username or password field) and directly uses that raw input to query the database.
*   **The Mechanism:** The attacker enters specific SQL commands into the input field to modify the backend SQL statement. They often use set operations or alter `WHERE` clauses to force the database to return alternate, unauthorized results.

## 2. Four Pervasive Types of SQL Injection
1.  **SQL Manipulation** (The most common type)
2.  **Code Injection**
3.  **Function Call Injection**
4.  **Buffer Overflows**

## 3. Deep Dive: SQL Manipulation
SQL manipulation attacks modify an existing SQL statement using set operations. They primarily target two elements:
*   The `WHERE` clause.
*   The `UNION` statement (used by attackers to grab and combine data from different, unauthorized tables).

### The "Always TRUE" Exploit (WHERE Clause)
A common goal of SQL manipulation during user authentication is to force the `WHERE` clause to always evaluate to `TRUE`, effectively bypassing the password check entirely.

*   **Original Intended Query:**
    `SELECT * FROM users WHERE username = 'alice' and PASSWORD = 'mypassword';`
*   **The Attack:** The attacker inputs `'mypassword' or 'a'='a'` into the password field.
*   **The Resulting Compromised Query:**
    `SELECT * FROM users WHERE username = 'alice' and PASSWORD = 'mypassword' or 'a'='a';`
*   **Why it works:** Because the letter 'a' will *always* equal 'a', the `OR` condition evaluates to `TRUE`. The database ignores the fact that the password might be wrong and grants access anyway.
