# Scanning Projects with Snyk

## 1. What is Snyk?
*   **Definition:** Snyk is an open-source Static Application Security Testing (SAST) tool and developer security platform.
*   **Purpose:** It helps teams identify, prioritize, and resolve security vulnerabilities in code, dependencies, containers, and infrastructure.
*   **Integration:** It integrates directly into development tools, workflows, and CI/CD automation pipelines, adding security knowledge directly to a developer's toolbox.

## 2. Setting Up Snyk with GitHub
The demo outlines the initial steps to connect Snyk to a code repository for automated scanning:
1.  **Account Creation:** Log into `snyk.io` and create a free account.
2.  **Integration:** Select GitHub as the integration source.
3.  **Authentication:** Configure the automation settings and authenticate the connection between Snyk and GitHub. This allows Snyk permission to view and scan the repositories.

## 3. Scanning a Repository
Once connected, you can scan existing repositories or import new ones.
*   **Importing a Repo:** Click "Monitor a public repository," type the repository name (e.g., `GitHub teacher/GitHub-slideshow`), and click "Add repo."
*   **Scanning Process:** Click "Import One repository." Snyk will download and analyze the code, which may take some time depending on the project's size.

## 4. Interpreting the Results
After the scan is complete, Snyk provides a detailed dashboard of the findings.

### Analyzing the File
*   You can expand the project to see exactly which files contain vulnerabilities.
*   *Demo Example:* The scan found 27 vulnerability issues inside a file called `gemfile.lock`.
*   **Context (`gemfile.lock` vs `requirements.txt`):** In a Ruby project, the `Gemfile.lock` file contains the names of all the project's dependent packages (similar to how a `requirements.txt` file works in a Python project).
*   **The Risk:** If your dependency file calls for a package that has a known vulnerability, your entire application inherits that vulnerability.

### Understanding the Vulnerability Dashboard
Clicking on a vulnerable file provides a detailed overview of the issues. The right-side panel displays critical metrics for prioritization:
*   **Severity Scores:** How dangerous the vulnerability is (e.g., Critical, High, Medium, Low).
*   **Fixability:** Whether a known patch or update exists for the issue.
*   **Exploit Maturity:** How easily an attacker could exploit the vulnerability in the wild.
*   **Status:** The current state of the issue.

### Remediation and Management
*   **Retest Now:** A button that forces Snyk to rescan the file to check if the vulnerabilities have been resolved.
*   **Dependencies Tab:** Provides a full, clear list of all software dependencies used in the project.
*   **Fixing (Paid Feature):** With the paid version of Snyk, you can often automatically apply fixes to these vulnerabilities directly from the dashboard.

## Quick Revision Questions & Answers

**1. What type of security testing tool is Snyk categorized as?**
*   **Answer:** A Static Application Security Testing (SAST) tool.

**2. What is the Python equivalent of a Ruby project's `gemfile.lock` file?**
*   **Answer:** `requirements.txt`.

**3. Why does scanning a file like `gemfile.lock` or `requirements.txt` reveal so many vulnerabilities?**
*   **Answer:** Because these files list all the external, third-party packages the project depends on. If any of those external packages have known flaws, Snyk flags them because they make your application vulnerable by association.

**4. When looking at a vulnerability in Snyk, what does the "Exploit Maturity" metric indicate?**
*   **Answer:** It indicates how easily an attacker could exploit that specific vulnerability in a real-world scenario (e.g., if proof-of-concept exploit code is already publicly available).

**5. How does Snyk integrate into the development workflow?**
*   **Answer:** By connecting directly to source control repositories like GitHub, allowing it to automatically scan code and dependencies as part of the standard development pipeline.
