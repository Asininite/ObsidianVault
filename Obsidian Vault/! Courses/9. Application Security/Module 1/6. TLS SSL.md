# Transport Layer Security (TLS) and Secure Sockets Layer (SSL)

## 1. Introduction: What are TLS and SSL?
*   **Definition:** TLS and SSL are cryptographic protocols designed to establish secure, encrypted connections between computers over a network (specifically, between a client/browser and a server).
*   **The Goal (Security):** The primary goal is to ensure that if a malicious actor intercepts the communication (e.g., a Man-In-The-Middle attack), the intercepted data is entirely unreadable and useless to them due to encryption.

## 2. TLS vs. SSL (The Difference)
*   **The Reality:** TLS is simply the modern successor to SSL. 
*   **History:** The first version of TLS (TLS 1.0) was introduced in 1999 as an upgrade to SSL 3.0.
*   **Usage Today:** While the industry still heavily uses the acronym "SSL" (or "TLS/SSL"), when people say SSL today, they are almost always referring to modern **TLS**.

## 3. How Modern TLS Works (The 4-Step Handshake)
To establish a secure connection, the client and server go through a "handshake" process consisting of four high-level steps:

1.  **Agree on TLS Version:** The two computers communicate and agree on which TLS version to use. They will always attempt to choose the highest, most secure version they both support. If they cannot find a matching supported version, the connection fails.
2.  **Agree on a Cipher:** Once the version is established, they agree on a supported **cipher**. A cipher is a specific algorithm/set of rules that dictates exactly *how* the information will be encrypted between them.
3.  **Verify Server Identity:** The client verifies the server's identity to ensure it isn't talking to an imposter. It does this by checking the server's **public key** and its **TLS certificate signature** (provided by a trusted Certificate Authority).
4.  **Generate Session Keys:** Finally, both computers use the public and private keys from the certificates to generate shared, temporary **session keys**. These secret keys are then used in the cipher (chosen in Step 2) to encrypt all further communication for that specific session.

## 4. Keeping TLS Secure in the SDLC
To maintain security throughout the Software Development Lifecycle (SDLC), developers must manage two critical components:

### A. Renewing Certificates (CI/CD)
*   TLS certificates eventually expire (usually every 1-2 years). If a certificate expires, browsers will flag the site as unsafe, breaking the connection.
*   **Best Practice:** Do not wait for expiration. Use Continuous Integration/Continuous Delivery (CI/CD) automation pipelines to automatically renew certificates early (e.g., every few months) to prevent outages.

### B. Updating Version and Cipher Support
*   **Stay Current:** Ensure your application always supports the newest, most secure version of TLS available.
*   **Drop the Old:** You must actively drop support for outdated, vulnerable versions of TLS (like TLS 1.0 and 1.1) to prevent attackers from forcing "downgrade attacks."
*   **Prefer Robust Ciphers:** Configure your servers to prioritize the strongest available ciphers and reject connections attempting to use weak or compromised ciphers.

## Quick Revision Questions & Answers

**1. What is the relationship between SSL and TLS?**
*   **Answer:** TLS is the modern, more secure successor to SSL. While the term "SSL" is still widely used, modern secure connections actually use TLS.

**2. During a TLS handshake, what happens if the client and server cannot agree on a supported TLS version?**
*   **Answer:** The connection process will fail, and they will not be able to communicate.

**3. What is the purpose of a "cipher" in the TLS process?**
*   **Answer:** A cipher is the specific algorithm or set of rules that defines exactly how the data will be encrypted and decrypted between the client and server.

**4. How does the client verify it is talking to the correct server and not an imposter?**
*   **Answer:** It verifies the server's identity using the server's public key and its TLS certificate signature.

**5. Why is it important to drop support for older versions like TLS 1.0 and 1.1 in your application?**
*   **Answer:** Older versions contain known vulnerabilities. If you support them, an attacker might force the connection to use the older, weaker protocol, compromising the security of the data.
