# Threat Monitoring: Repositories and Containers

## 1. What is Threat Monitoring?
Threat monitoring is the proactive practice of scanning code repositories and container images to identify security risks before they reach production. It helps developers discover vulnerabilities like:
*   **Password Mishandling:** Hardcoded credentials or insecure storage.
*   **Protocol Insecurities:** Use of outdated or weak network protocols.
*   **Incorrect Permissions:** Misconfigured access rights that could be exploited.

### SDLC Integration
Threat monitoring is not a one-time event; it is integrated across three critical stages of the Software Development Lifecycle (SDLC):
1.  **Develop:** Scanning in IDEs (Integrated Development Environments) to catch bugs as you write code.
2.  **Test:** Automated scanning during the build and testing phase.
3.  **Deploy:** Final checks before the application goes live in the production environment.

---

## 2. Repository Scanning (Source Control)
Because repositories (like GitHub) are often collaborative or open-source, they are high-risk areas for security threats.

*   **Code Checkers:** These tools scan source code to analyze coding syntax, style, documentation, and security vulnerabilities. They provide immediate insights and "pointers" on where to fix the code.
*   **SCM Integration:** Modern threat monitoring tools integrate directly with Source Control Management (SCM) tools.
    *   **Automated Fixes:** Some scanners can generate automatic "fix" pull requests when they find a vulnerability.
    *   **Commit Verification:** Tools can require commits to be signed with a PGP (Pretty Good Privacy) key to ensure that only trusted sources are contributing to the code.
*   **Vulnerability Databases:** Scanning tools reference standardized databases of known threats, such as the **OWASP Top 10** (Open Web Application Security Project), to ensure they are catching the most common and dangerous exploits.

---

## 3. Container Scanning
Container scanning is the process of examining container images for security threats.

### Why Containers are Vulnerable
Containers are not just your application code; they are "packages" that include library dependencies, runtimes, and the base operating system. Even if your custom code is secure, your application may be vulnerable because of an insecure dependency or a compromised base image.

### The "Layering" Requirement
Container images are usually built on top of other images (base images). Because each layer could potentially contain vulnerabilities:
*   **Scope:** Scanning must include the **base image** plus **all layered container images**.
*   **Risk:** If you only scan the top layer, you leave your application exposed to vulnerabilities hidden deep within the underlying layers.

---

## Deep Dive: Repository vs. Container Scanning
It is helpful to view these as two different "defense-in-depth" strategies:

| Feature | Repository Scanning | Container Scanning |
| :--- | :--- | :--- |
| **Primary Target** | Your custom source code and scripts. | The entire bundled runtime environment (OS + Dependencies). |
| **Tool Type** | Static Analysis / Linters / SCM Hooks. | Image Scanners (e.g., Snyk, Clair, Trivy). |
| **Key Risk** | Insecure coding practices, credentials in commits. | Vulnerable library versions, outdated OS packages in the base image. |

## Quick Revision Questions & Answers

**1. At what three stages of the SDLC should you integrate threat monitoring?**
*   **Answer:** Develop, Test, and Deploy.

**2. What is the primary risk factor for code repositories mentioned in the transcript?**
*   **Answer:** They are often collaborative and open-source, making them susceptible to human error, leaked credentials, and unauthorized contributions.

**3. If your custom application code is perfectly secure, why would you still need to perform container scanning?**
*   **Answer:** Because your container likely includes third-party library dependencies and a base operating system image, both of which may have their own separate vulnerabilities.

**4. What is the purpose of PGP key signing in code repositories?**
*   **Answer:** It serves as a verification method to prove that the code commit came from a trusted source.

**5. What is the "OWASP Top 10" and why do scanners reference it?**
*   **Answer:** It is a standard list of the ten most critical web application security risks. Scanners reference it to ensure they are proactively checking for the most dangerous and common exploits currently threatening applications.
