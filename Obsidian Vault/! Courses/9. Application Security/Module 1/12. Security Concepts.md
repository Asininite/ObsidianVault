# Security Concepts and Terminology

## 1. Core Security Definitions

To effectively build secure applications, you must be able to clearly distinguish between these fundamental terms:

- **Authentication (AuthN):** The process of verifying a user’s identity. It asks, "Are you really who you claim to be?"
    
- **Authorization (AuthZ):** The process of determining a user’s access rights. It asks, "Now that I know who you are, what are you permitted to do?"
    
- **Encryption:** The process of encoding information so that only users with the correct access rights can decode and read it.
    
    - **Symmetric Encryption:** The same key is used for both encrypting and decrypting data.
        
    - **Asymmetric Encryption:** Different keys are used; one for encrypting and a different one for decrypting.
        
- **Integrity:** The process of ensuring that data has not been changed or tampered with by an unauthenticated source.
    
    - **Mechanism:** Secure hash algorithms are commonly used here. A hash creates a unique fingerprint of the data. If the data is tampered with, the hash will change, alerting the system that the data is no longer trustworthy.
        

## 2. CI/CD: Continuous Integration and Delivery

CI/CD is the application of automation within the software development pipeline.

- **Continuous Integration (CI):** The practice where new code changes are regularly built, tested, and merged into a shared repository.
    
- **Continuous Delivery (CD):** Tested changes are automatically released to a development, test, or staging environment.
    
- **Continuous Deployment (CD):** Tested changes are automatically deployed directly to production.
    

## 3. Integrating Security into the CI/CD Pipeline

Security is not an afterthought; it is a vital component of the CI/CD process:

1. **Early Scanning:** Perform source code scanning and analysis during the CI stage to expose vulnerabilities before code is merged.
    
2. **Integrated Testing:** Run security tests (like automated vulnerability scans) alongside standard integration and functional tests in the pipeline.
    
3. **Runtime Security:** Even after deployment, the system should continuously detect and report new threats that arise while the application is running in production.
    

## Deep Dive: Why integrate security into CI/CD?

In a DevOps model, speed is the priority. If security teams manually check code _after_ it’s been deployed, it creates a massive bottleneck. Integrating security into the CI/CD pipeline enables "Shift-Left" security—the practice of moving security checks to the earliest possible point in the development cycle.

When security is automated within the pipeline, developers get immediate feedback ("failing the build" because of a security vulnerability), allowing them to fix bugs while the code is still fresh in their minds, which is significantly faster and cheaper than fixing a breach in production.

## Quick Revision Questions & Answers

**1. What is the difference between Authentication and Authorization?**

- **Answer:** Authentication verifies _who_ you are. Authorization determines _what_ you are allowed to do.
    

**2. Which encryption type uses the same key for both encryption and decryption?**

- **Answer:** Symmetric encryption.
    

**3. If you apply a hash algorithm to a file and the resulting hash is different from the original hash, what does that indicate?**

- **Answer:** It indicates that the data has been modified or tampered with.
    

**4. What are the two distinct meanings of "CD" in the CI/CD pipeline?**

- **Answer:** Continuous Delivery (automatically releasing to a non-production environment) and Continuous Deployment (automatically deploying to production).
    

**5. How can you detect threats that arise after the code has been deployed to production?**

- **Answer:** By integrating runtime security to monitor the production environment for anomalies.
