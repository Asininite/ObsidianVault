# Introduction to Synthetic Monitoring

## 1. What is Synthetic Monitoring?

- **Definition:** Synthetic monitoring (also known as active monitoring or synthetic testing) is a proactive method used to evaluate application and website performance by simulating real user paths and interactions.
    
- **Mechanism:** It utilizes automated scripts or bots to execute a predefined set of actions (e.g., logging in, searching, adding items to a cart, checking out) periodically from various checkpoints.
    
- **Focus:** It focuses on predicting user experience, testing availability, and identifying performance degradation before actual users are impacted.
    

## 2. Core Mechanics: How Synthetic Monitors Work

Rather than waiting for real traffic, synthetic monitors act as active probes:

- **Global Checkpoints:** Tests are initiated by virtual clients running on different operating systems across a network of checkpoints distributed globally.
    
- **Key Metrics Measured:**
    
    1. **Availability:** The uptime of a resource over time (e.g., $99.99\%$ uptime).
        
    2. **Responsiveness:** The latency/response time of the resource in milliseconds over time.
        
- **Common Targets:** Websites, web services, DNS, APIs (including third-party payment gateways, ads, and CDNs), and physical servers.
    

## 3. The Synthetic Monitoring Process (Step-by-Step)

Depending on whether an error is encountered, the execution loop consists of 4 to 5 distinct steps:

```
[System Selects Checkpoint] ──> [Checkpoint Initiates Test] ──> [Checkpoint Reports Result]
                                                                        │
                                                                        ▼
[System Sends Alert] <── [Error Confirmed] <── [Re-test from Alternate Checkpoint (If Error)]
```

1. **Target Selection:** The monitoring system selects a specific global checkpoint and transmits testing instructions.
    
2. **Execution:** The checkpoint initiates contact with the target web/network entity, evaluates the response, and proceeds based on the specified test parameters.
    
3. **Reporting:** The checkpoint reports its telemetry and findings back to the central monitoring system.
    
4. **Logging:** The system records this data for long-term historical reporting.
    
5. **Error Verification (Conditional):** If the initial check returns an error, the system immediately triggers an alternate test from a _different_ checkpoint. If the second checkpoint confirms the same failure, the error is marked as **confirmed**, and an alert is dispatched based on escalation schedules.
    

_Note: This cycle can run as frequently as every minute or up to once an hour._

## 4. Why Use Synthetic Monitoring? (Business and Technical Benefits)

- **Proactive Alerting:** Outages and database performance degradations are identified and flagged before real users attempt to access the system.
    
- **Vendor Accountability (SLA/SLO Validation):** Allows companies to monitor the performance of external dependencies (e.g., CDNs, analytics, and third-party payment systems) to ensure vendors are meeting their Service Level Agreements.
    
- **Geographic Testing:** Simulates user transactions from diverse geographical locations to isolate region-specific routing or latency bottlenecks.
    
- **Baseline Consistency:** By removing the chaotic variables of real-world end-user setups (different devices, networks, and browsers), it establishes a highly consistent, controlled testing environment for measuring baseline performance trends.
    

## 5. Synthetic Monitoring vs. Real User Monitoring (RUM)

While both are critical performance testing methodologies, they approach visibility from opposite directions:

|   |   |   |
|---|---|---|
|**Feature**|**Synthetic (Active) Monitoring**|**Real User (Passive) Monitoring**|
|**Methodology**|Active / Simulated|Passive / Real-world|
|**Implementation**|Simulated virtual clients and bots|JavaScript snippet embedded in the page|
|**Variables**|Eliminates variables (consistent baseline)|Captures high diversity (various browsers, networks, locations)|
|**Main Advantage**|Catches issues _before_ users arrive; monitors during low/no-traffic periods|Captures actual user behaviors, satisfaction trends, and long-term habits|
|**Ideal For**|Immediate issue resolution, API uptime, SLA validation, and regression testing|Analyzing user paths, front-end optimization, and organic user experience|

**The Golden Rule:** Synthetic and Real User Monitoring work best in conjunction. RUM trends can be analyzed to determine which user paths are most heavily utilized, which can then be used to configure more accurate, high-priority synthetic test cases.

## Quick Revision Questions & Answers

**1. What is the fundamental difference between Synthetic Monitoring and Real User Monitoring (RUM)?**

- **Answer:** Synthetic Monitoring is active and proactive; it uses virtual clients and bots to simulate user actions in a controlled environment. RUM is passive; it injects a JavaScript snippet to observe and report on real users as they navigate your live application.
    

**2. Why does the synthetic monitoring system run a secondary test from a** _**different**_ **checkpoint when an error is detected?**

- **Answer:** To prevent false positives. If only one checkpoint fails, it could indicate a localized network issue near that specific checkpoint. If a second, geographically distinct checkpoint also fails, the error is confirmed as a genuine system outage.
    

**3. How does synthetic monitoring assist in validating Service Level Agreements (SLAs) with third-party vendors?**

- **Answer:** Because it runs continuous, structured tests against third-party endpoints (like payment processors or CDNs), it compiles exact availability percentages and latency logs, allowing organizations to hold vendors accountable if they violate agreed-upon performance thresholds.
    

**4. Can synthetic monitoring detect performance issues when there is zero organic user traffic on a website?**

- **Answer:** Yes. Because it relies on simulated transactions executed by scheduled bots, it can continuously test system health $24/7$, even during off-peak hours with no real visitors.
    

**5. What are some of the complex, multi-step business transactions that synthetic monitoring is capable of simulating?**

- **Answer:** It can simulate full transactional workflows, including logging into an account, searching for a product, filling out information forms, adding items to a shopping cart, and executing the checkout process.
