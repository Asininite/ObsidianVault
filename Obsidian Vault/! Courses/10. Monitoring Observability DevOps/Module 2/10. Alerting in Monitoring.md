# Alerting in Monitoring

## 1. What is Alerting?

- **Definition:** Alerting is the **responsive element** of a monitoring system. While monitoring collects and watches data, alerting proactively notifies operators of potential issues.
    
- **Goal:** Detect and address issues before they impact the end user.
    
- **Primary Outputs:**
    
    1. **Notifications:** Informing staff that a condition was met.
        
    2. **Automated Actions:** Executing programmatic/scripted mitigation tasks to resolve the issue automatically.
        

## 2. The Alerting Process (The Feedback Loop)

1. **Collection & Analysis:** The monitoring system collects metrics and analyzes them.
    
2. **Alarm Triggered:** An anomaly or failure triggers an alarm, dispatching an alert.
    
3. **Investigation:** Appropriate staff investigates the root cause (working backward from the metric).
    
4. **Mitigation:**
    
    - **Success:** The fix is found, the system returns to balance, and the alarm clears.
        
    - **Failure:** Metrics do not improve, requiring an alternative mitigation strategy.
        

## 3. The Four Types of Alerts

- **Metric Alerts:** Based on raw data (e.g., CPU, RAM, database latency). Excellent for understanding overall infrastructure health and usage trends.
    
- **Log Alerts:** Use analytics queries to check resource logs at predefined intervals. Vital for troubleshooting specific event trails.
    
- **Activity Log Alerts:** Automated rules that trigger when new events match predefined conditions; helps reduce the manual workload of log reviews.
    
- **Smart Detection:** Often provided by cloud platforms (like Application Insights); proactively analyzes telemetry to automatically warn of performance or failure anomalies.
    

## 4. Threshold Strategy: Finding the Balance

Creating effective alerts requires fine-tuning sensitivity:

- **Too Broad (Insensitive):** The system may fail to detect real problems, allowing performance to degrade until a full outage occurs.
    
- **Too Sensitive (Noisy):** Validates normal system operations as "anomalies," causing alert fatigue.
    
- **Best Practice:** Regularly audit baselines. If alarms go off for normal operations, adjust the thresholds to improve specificity.
    

## 5. Popular Open-Source Alerting Tools

- **Bosun:**
    
    - Features: Simple graphs, powerful expression language for rules.
        
    - Notifications: Limited to email/HTTP (requires customization for Slack/other integrations).
        
- **Cabot:**
    
    - Features: API-hooking (uses a pull model), stores data in Postgres/Redis, supports on-call rotation (Rota) via Google Calendar.
        
    - Focus: Does not collect data itself; hooks into other alerting tool APIs.
        
- **StatsAgg:**
    
    - Features: Metrics aggregation platform, acts as a proxy.
        
    - Inputs: Supports Graphite, StatsD, InfluxDB, OpenTSDB.
        
    - Focus: Alerting by _service_ rather than host/instance.
        

## Quick Summary

Alerting disengages admins from manual 24/7 watching by allowing them to define "normal" operational parameters. By combining passive monitoring with intelligent, automated alerts, teams can minimize downtime, save operational costs, and respond to issues immediately.
