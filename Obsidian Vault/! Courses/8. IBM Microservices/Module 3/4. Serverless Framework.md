 # The Serverless Framework

## 1. What is the Serverless Framework?

- **Definition:** The Serverless Framework is a free, open-source web framework written in Node.js.
    
- **The Goal:** It provides developers with a Command Line Interface (CLI) that offers structure, automation, and best practices right out of the box. It allows you to focus purely on building sophisticated, event-driven serverless architectures rather than wrestling with infrastructure setup.
    
- **Cloud Agnostic:** While it was originally designed specifically to provision Amazon Web Services (AWS Lambda), it now fully supports other major cloud providers like Microsoft Azure, Google Cloud Platform, and Apache OpenWhisk.
    

## 2. Core Concepts

The framework helps you manage four primary components of a serverless architecture:

### A. Functions

- **Definition:** A function is an independent unit of deployment (like a microservice). It is merely code deployed in the cloud, typically written to perform one single, highly specific task.
    
- **Examples:** Saving a new user to a database, compressing an image, or running a scheduled job at midnight.
    

### B. Events

- **Definition:** Events are the specific triggers that wake up and execute your functions.
    
- **Examples:** An HTTP request hitting an API Gateway URL, a new file landing in an AWS S3 bucket, or a timer going off.
    

### C. Resources

- **Definition:** Resources are the actual infrastructure components that your functions need to use or interact with to get their job done.
    
- **Examples:** A managed cloud database (like DynamoDB), an object storage bucket (like S3), or an external message queue.
    

### D. Services (The Core Unit)

- **Definition:** A "Service" is the Serverless Framework's primary unit of organization. You can think of a Service as a single project file. _Note: A large, complex application might be composed of multiple different Services._
    
- **Configuration:** Every Service is controlled by a single configuration file called **`serverless.yml`**.
    

## 3. The `serverless.yml` Configuration File

This is the most important file in the framework. It acts as the master blueprint for your application.

- **What it does:** You use this file to explicitly define all your Functions, the Events that trigger them, and the Resources they need.
    
- **Deployment:** When you run the `serverless deploy` command in the CLI, the framework reads this entire file and deploys _everything_ defined in it all at once to your chosen cloud provider.
    

## 4. Building and Testing a Basic Function (AWS Example)

The video outlines a rapid workflow for getting a "Hello World" app live on AWS.

1. **Prerequisites:** You must have your AWS credentials already set up locally on your machine.
    
2. **Install the CLI:** Install the framework globally on your computer using npm: `npm install -g serverless`
    
3. **Create the Project:** Run the `serverless` command. The CLI provides a wizard to help you generate a boilerplate template (e.g., an AWS HTTP API using Python).
    
4. **Deploy:** The framework automatically bundles your code, provisions the AWS API Gateway, and gives you a live, public URL.
    
5. **Test and Iterate:** You open the URL in your browser to test it. If you need to make a change (like updating the code to say "Hello World v2"), you simply save the file, run `serverless deploy` again, and refresh the browser.
    

## Quick Revision Questions & Answers

**1. Is the Serverless Framework only compatible with Amazon Web Services (AWS)?**

- **Answer:** No. While it was originally built for AWS, it is now cloud-agnostic and supports Microsoft Azure, Google Cloud Platform, and Apache OpenWhisk.
    

**2. What is the primary configuration file used to manage a project in the Serverless Framework?**

- **Answer:** The `serverless.yml` file.
    

**3. In the context of the Serverless Framework, what is the difference between an Event and a Function?**

- **Answer:** An **Event** is the trigger (like an HTTP request or file upload). The **Function** is the actual code that executes in response to that trigger.
    

**4. What language is the Serverless Framework itself written in?**

- **Answer:** Node.js.
