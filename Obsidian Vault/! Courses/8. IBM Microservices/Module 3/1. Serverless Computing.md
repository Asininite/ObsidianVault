# Introduction to Serverless Computing

## 1. What is Serverless Computing?

- **Definition (CNCF):** The concept of building and running applications that do not require server management.
    
- **The Goal:** It offloads the entire responsibility of infrastructure management (hardware, software setup, security, scalability) to the cloud provider, enabling developers to focus purely on the application's business logic.
    
- **The Architecture:** Serverless computing is essentially a combination of two service models:
    
    - **FaaS (Function-as-a-Service):** Platforms used to actually run the core application code in the form of independent functions.
        
    - **BaaS (Backend-as-a-Service):** Cloud services used to support the functions (e.g., cloud databases, object storage, and message queues).
        

## 2. The Evolution of IT Computing

The history of computing shows a progressive trend toward faster deployments, shorter lifespans, and increased productivity.

1. **Traditional Computing:** Uses physical bare-metal machines. Hampered by massive upfront investments and capacity planning. Takes _weeks/months_ to deploy; lifespan of _years_.
    
2. **Virtualization (VMs):** Allowed multiple virtual machines on a single physical host, enabling faster provisioning. Takes _minutes_ to deploy; lifespan of _days/weeks_.
    
3. **Containers (e.g., Docker/Kubernetes):** Based on OS virtualization, making them much lighter than VMs. Takes _seconds_ to deploy; lifespan of _minutes/hours_.
    
4. **Serverless:** Abstracts both the infrastructure and software environments. Takes _milliseconds_ to deploy; lifespan of _seconds_.
    

## 3. Key Characteristics of Serverless

- **Hostless:** Developers do not procure, manage, or maintain any servers.
    
- **Elastic:** Autoscaling is immediate and inherent to the platform.
    
- **Automated Load Balancing:** The provider automatically distributes incoming traffic across backend systems.
    
- **Stateless:** Functions do not store local data between executions, resulting in faster performance and higher scalability.
    
- **Event-Driven:** Functions do not run continuously. They are triggered _only_ when specific events occur (e.g., a user clicks a button, or a file is uploaded).
    
- **High Availability:** Provided natively with no extra effort or cost to the developer.
    
- **Usage-Based Billing:** Granular billing where the client is billed _only_ for the exact compute time used. You do not pay for CPU idle time.
    

## 4. How Serverless Functions Work

The serverless workflow drastically simplifies the traditional container deployment process:

1. **Write:** The developer writes a specific function in a supported language (Python, Java, Node.js, Go, etc.).
    
2. **Upload:** The developer uploads that raw code function to the cloud provider.
    
3. **Define Trigger:** An event is defined to trigger the function (e.g., an HTTP request or a database update).
    
4. **Execute:** Once the event occurs, the cloud provider instantly spins up a container object in the background, runs the function, and then destroys the container once the task is complete.
    

## 5. Benefits of Serverless

Because developers spend zero time on operational considerations (like OS updates, patching, or network utilization), they gain massive benefits:

- Can build functions using any popular programming language.
    
- Can extend app functionality easily by adding isolated features.
    
- Can perform better, highly focused testing (since a function performs only one specific task at a time).
    
- Can optimize the user experience and overall app quality.
    

## 6. Comparing Cloud Service Models (Responsibility Shift)

Understanding who manages what is crucial for defining cloud models:

- **Traditional (On-Premises):** You manage the _entire_ stack (Networking, Storage, Servers, Virtualization, OS, Middleware, Runtime, Data, Application).
    
- **IaaS (Infrastructure-as-a-Service):** The cloud provider manages the bottom infrastructure (Networking up to Virtualization). You manage everything from the OS up to the Application.
    
- **PaaS (Platform-as-a-Service):** The cloud provider manages everything up to the Runtime. You only manage the Application and the Data.
    
- **Serverless:** The cloud provider manages everything up to the Data layer. **You only manage the Application layer (the code functions).**
    
- **SaaS (Software-as-a-Service):** The cloud provider manages the _entire_ stack.
