# Creating REST APIs with Python and Flask

## 1. Why Python for REST APIs?

Python is a highly versatile, readable, and powerful programming language. It is widely used across multiple domains:

- **Web Development:** Using frameworks like Flask and Django.
    
- **Data Science & Engineering:** Using libraries like SciPy for scientific and numeric computing.
    
- **AI & Machine Learning:** It is the industry-standard language for AI development.
    
- **The Benefit:** Because Python is so easy to read and integrates systems effectively, it is a top choice for rapidly building and deploying RESTful APIs and microservices.
    

## 2. What is Flask?

Flask is classified as a **micro web framework** for Python.

- **"Micro" Explained:** In this context, "micro" does _not_ mean it can only build small applications. It means the framework is extremely lightweight and **un-opinionated**.
    
- **Un-opinionated:** Unlike larger frameworks (like Django) that force you to use their specific database structures or template engines, Flask gives you a blank canvas. It does not require specific tools or libraries.
    
- **Why it's great for APIs:** Because REST APIs usually just need to receive HTTP requests and spit back JSON data (no complex HTML templates or heavy frontend logic needed), Flask's lightweight simplicity makes it the perfect tool.
    

## 3. Environment Setup

To build a Flask API, you only need a few basic tools:

1. **Python 3:** The runtime environment.
    
2. **pip:** The official Python package manager (used to install external libraries).
    
3. **Installation:** You install Flask by simply running the command `pip install Flask` in your terminal.
    

## 4. Building a Flask Application (Step-by-Step)

### Step 1: The "Hello World" App (`hello.py`)

- You create a simple Python script to initialize the Flask server.
    
- **Hosting:** When you run the server, it hosts the application locally on your machine.
    
- **Accessing the App:** You open a web browser and navigate to `127.0.0.1:5000`.
    
    - _Deep Dive:_ `127.0.0.1` is the universal IP address for **localhost** (your own computer). `5000` is the default **port** number that Flask uses to listen for incoming web traffic.
        
- **Result:** The browser makes a `GET` request, and the screen displays "Hello World".
    

### Step 2: Creating a Microservice Endpoint (`products.py`)

To build a functional REST API, you need to define endpoints (URLs) that return specific data.

- **The Setup:** You create a file called `products.py` and define a default list of products in the Python code.
    
- **No Database (In-Memory Storage):** Because this is a simple example, you aren't connecting to a real database (like PostgreSQL or MySQL). The products are just stored in the server's temporary RAM.
    
    - _The Consequence:_ Every time you stop and restart the Flask server, any new products added will be erased, and it will reset back to the default list.
        
- **Defining the GET Method:** You create a route (e.g., `/products`) and explicitly tie it to the HTTP `GET` method. When a user requests that URL, Flask returns the list of products.
    
- **HTTP 200 OK:** When Flask successfully returns the data, it implicitly attaches a **Status Code of 200** to the response. In the standard HTTP protocol, `200` universally means "OK" (the request was received, understood, and successfully processed).
    

## Quick Revision Questions & Answers

**1. Why is Flask classified as a "micro" web framework?**

- **Answer:** Because it is lightweight and un-opinionated. It doesn't force the developer to use specific databases, libraries, or template engines, keeping the core incredibly simple.
    

**2. What is `pip`?**

- **Answer:** It is the standard package manager for Python, used to install and manage external software libraries (like Flask).
    

**3. When you run a standard Flask app on your computer, what IP address and port does it default to?**

- **Answer:** It defaults to `127.0.0.1` (localhost) on port `5000`.
    

**4. If your API does not use a persistent database and just stores a list of products in the Python code, what happens when the server restarts?**

- **Answer:** Any changes made to the data during runtime are lost, and the application resets to the original, hardcoded list of products.
    

**5. What does the HTTP status code `200` mean?**

- **Answer:** It means "OK". The client's request was successfully received and processed by the server.
