# IBM Cloud Code Engine

## 1. The Challenges of Self-Hosting Microservices

Deploying and self-hosting microservices requires significant operational overhead. Developers must tackle several non-trivial challenges:

- **Production-Readiness:** Manually configuring library dependencies, resources, and credentials.
    
- **Compilation:** Compiling and building code into an executable binary suited for the hosting environment.
    
- **Infrastructure Selection:** Carefully choosing and managing the underlying web servers, operating systems, networks, and databases.
    
- **Dynamic Scaling:** Manually configuring systems to scale up during peak traffic (like holidays) and scale down when traffic decreases.
    
- **Service Communication:** Ensuring reliable and secure network communication between multiple related microservices.
    
- **Observability:** Setting up custom logging, monitoring, and dashboards to ensure stability and foresee production issues.
    

## 2. Deep Dive: Python Web Server Interfaces

If you build a microservice using Python (like Flask or Django), it cannot provide services directly to the internet. It requires a specific web server interface or entry point.

- **WSGI (Web Server Gateway Interface):** The traditional standard for Python communication. It supports **synchronous** service calls only.
    
    - _Popular Servers:_ Green Unicorn (Gunicorn), uWSGI.
        
- **ASGI (Asynchronous Server Gateway Interface):** The modern interface that supports **asynchronous** code execution.
    
    - _Popular Servers:_ Daphne, Hypercorn.
        
- _The Problem:_ Regardless of which interface you choose, you still have to manually provision the infrastructure (a laptop, a dedicated workstation, or a sophisticated cluster) to run these servers.
    

## 3. What is IBM Cloud Code Engine?

- **Definition:** A fully managed, serverless platform designed to completely abstract the operational burden of building, deploying, and managing workloads.
    
- **The Goal:** To allow developers to push their code to the cloud and entirely disregard the underlying infrastructure.
    
- **Architecture:** It acts as a comprehensive hybrid, combining the features of Platform-as-a-Service (PaaS), Containers-as-a-Service (CaaS), and serverless deployment models.
    
- **Workloads:** It can run microservices, web apps, event-driven functions, and batch jobs.
    

## 4. The Three Main Use Cases (Deployment Modes)

IBM Cloud Code Engine handles workloads in three primary ways:

1. **Deploy a Built Application:** You can directly deploy an already-built application (like a pre-packaged container image representing a microservice or web app).
    
2. **Push Source Code Directly:** You can point Code Engine to a remote repository (like GitHub) or a local workspace. The platform will automatically extract the source code, build the application for you, and deploy it, saving massive amounts of time.
    
3. **Run Batch Jobs:** You can create and execute background tasks (like data processing or analytics). Because these jobs run on the exact same infrastructure as your microservices, they can communicate and work seamlessly together.
    

## 5. Key Benefits of Code Engine

- **Zero Infrastructure Management:** It takes care of all cluster management, provisioning, configuring, and server maintenance.
    
- **Speed:** It can build and deploy applications in seconds (crucial for pushing emergency updates).
    
- **Auto-scaling:** It automatically scales your workloads up and down based on real-time traffic.
    
- **Security:** It provides secure connections via TLS (Transport Layer Security), fully isolates workloads, and controls access permissions using IBM Cloud IAM (Identity and Access Management).
    
- **Ecosystem Integration:** It fully integrates into the IBM Cloud, granting your applications easy access to the full catalog of IBM Cloud services.
    

## Quick Revision Questions & Answers

**1. If you write a Python microservice using Flask, what type of interface do you need to handle synchronous web requests?**

- **Answer:** A WSGI (Web Server Gateway Interface) server, like Gunicorn.
    

**2. What is the primary goal of the IBM Cloud Code Engine?**

- **Answer:** To remove the operational burden of managing infrastructure, allowing developers to focus entirely on writing code.
    

**3. If you don't want to build your own container images, how can IBM Cloud Code Engine help?**

- **Answer:** You can use its "Source Code" deployment mode, where you simply provide a link to your GitHub repository and Code Engine will build and deploy the application for you automatically.
    

**4. Can you run heavy data-processing tasks on IBM Cloud Code Engine?**

- **Answer:** Yes, by utilizing its third main use case: running Batch Jobs.
