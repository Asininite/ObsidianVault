# Deploying and Running Applications on IBM Cloud Code Engine

## 1. Two Main Modes of Deployment

When deploying an application to IBM Cloud Code Engine, the underlying requirement is always the same: Code Engine needs a container image to run. However, you have two choices for how that image gets built and provided to the platform:

### Mode 1: Deploy from a Container Image (Manual Build)

- **The Process:** The developer manually builds the container image locally (using `docker build`) and pushes it to a public or private container registry (like Docker Hub or IBM Container Registry).
    
- **Code Engine's Role:** Code Engine simply pulls that pre-built image from the registry (using registry access credentials if it is private) and deploys it.
    

### Mode 2: Deploy from Source Code (Automated Build)

- **The Process:** The developer provides the raw source code along with a `Dockerfile` or relies on Cloud Native Buildpacks.
    
- **Code Engine's Role:** Code Engine takes over the heavy lifting. It automatically builds the container image directly from the source code, pushes it to an internal registry, and then deploys it.
    

> **Deep Dive: Which mode should you choose?**
> 
> - **Choose Mode 1 (Container Image)** if your team already has a mature, automated CI/CD pipeline (like Jenkins or GitHub Actions) that builds and tests container images before deployment, or if you are using pre-packaged third-party software.
>     
> - **Choose Mode 2 (Source Code)** if you want to rapidly prototype, lack a dedicated CI/CD pipeline, or simply want to offload the operational burden of image building entirely to the cloud provider.
>     

## 2. Management Interfaces

IBM provides two primary ways to interact with Code Engine and deploy these applications:

- **IBM Cloud Console (GUI):** A well-designed, user-friendly web portal. It is highly visual and allows end-users to create, configure, and deploy applications with just a few clicks. It is ideal for beginners or visual configuration.
    
- **IBM Cloud CLI (Command Line Interface):** A terminal-based tool. It is ideal for developers who prefer typing commands or need to script and automate precise deployment processes.
    

## 3. Deployment Workflow: IBM Cloud Console

Deploying via the graphical interface involves a few streamlined steps:

1. **Name the Application:** Provide a unique name for your application within the project.
    
2. **Select the Source:** Choose whether you are deploying from a pre-built "Container Image" or raw "Source Code".
    
3. **Provide Image Reference:** Paste the URL/reference to where the image is stored (e.g., `us.icr.io/my-namespace/my-app:v1`).
    
4. **Configure Registry Access:** If the image is in a private registry, you must provide the security credentials (Registry Access) so Code Engine has permission to download it.
    
5. **Deploy and Test:** Once created, Code Engine automatically provisions the app. Within a few minutes, it will provide a publicly accessible **Endpoint URL** that routes directly to your live application.
    

## 4. Deployment Workflow: IBM Cloud CLI

For those using the terminal, the deployment process is handled using the `ibmcloud ce` (Code Engine) command group.

### A. Creating and Deploying the App

The primary command to create an application is `ibmcloud ce app create`.

**Key Arguments:**

- `--name`: The name of the application.
    
- `--image`: The reference URL to the container image in the registry.
    
- `--registry-secret`: The access credentials required if the registry is private.
    

**Example Command:**

`ibmcloud ce app create --name helloworldapp --image us.icr.io/my-namespace/hello:v1 --registry-secret myregistry`

### B. Retrieving Application Details

Once deployed, you need to find the live URL of your application to test it. You use the `ibmcloud ce app get` command for this.

**Key Arguments:**

- `--name`: The name of the deployed application.
    
- `--output`: The specific format of the data you want returned (e.g., just the URL).
    

**Example Command:**

`ibmcloud ce app get --name helloworldapp --output url`

_(This command will print the publicly accessible web address of your newly deployed application directly into your terminal.)_

## Quick Revision Questions & Answers

**1. What is the fundamental difference between deploying from a Container Image versus deploying from Source Code in IBM Cloud Code Engine?**

- **Answer:** The difference lies in who builds the image. Deploying from an image requires the developer to build and push the container beforehand. Deploying from source code means Code Engine automatically builds the container image for you.
    

**2. If your container image is stored in a private IBM Cloud Container Registry, what must you provide to Code Engine so it can deploy the app?**

- **Answer:** You must provide the "Registry Access" (credentials/secrets) so Code Engine has the necessary permissions to authenticate and pull the private image.
    

**3. What is the primary CLI command used to deploy a brand new application to Code Engine?**

- **Answer:** `ibmcloud ce app create`
    

**4. What does Code Engine generate for you once an application is successfully deployed?**

- **Answer:** It generates a publicly accessible Endpoint URL that leads directly to your live application.
